# 阶段6：保存失败提示与原操作重试预审

日期：2026-10-18。分支：`guan/stage6-local-storage`。

## 结论与范围

本批已实现自有恢复协调模块、存储桥候选后继和声明式保存状态条，**尚未接入原画布或3100**。原作者仓库、历史批准源码、JSON/patch和检查器均不修改；不读真实Chrome数据或Keychain，不迁移旧数据，不重启服务，不提交、推送或发布。

用户故事：编辑 → 桥内合并保存 → 不可变操作队列 → 受限本机API → SQLite → 匹配ACK → 页面保存状态；失败后明确提示保留页面，由用户重试原请求，再按顺序提交后续编辑。

原画布没有应用级保存恢复插件槽。本批仅准备5个自有文件的精确后继，不能把“继续推进”当作具体接入批准。浏览器预审未通过前，也不申请生产接管。

## 已发现的问题与候选修正

1. 原适配器在某个请求未确认时阻止同命名空间后续写入，但不负责保存这些后续编辑。本批在外层按命名空间保留不可变FIFO操作，包含修改、删除和清空，不跨过失败队首。
2. 原桥的失败Map与底层待重试请求分别存在。仅重试底层可能仍显示失败；只清Map又可能假报成功。本批等待失败原操作、后续编辑、重试期间新编辑及桥内400ms合并保存全部收到ACK，排空成功后才清除失败Map。
3. 已提交但ACK丢失时不能换ID重新写。本批调用原适配器的retry，复用完整原请求与operationId；仅在明确没有待重试请求的编码/预发送失败处，重新执行原快照，仍不得跳过错误。
4. 原调用者即使未await也有可见失败状态。候选React组件显示保存中、已保存、未确认和重试中；失败常驻，成功2.5秒后消失，关闭时仍有beforeunload提醒。
5. revision冲突、凭据拒绝、容量或快照错误保持失败，不自动采纳远端版本、不强制覆盖、不清除未知状态、不回退浏览器库。

## 重要数据边界

队列只在当前页面内存，不是断电、崩溃或刷新后可恢复的离线日志。保存失败时须保留页面，不能声称“关闭后自动恢复未保存内容”。浏览器可能忽略关闭提示，因此它也不是绝对的数据保护保证。

状态通知只含状态、计数、命名空间和受限错误码，不传画布内容、路径、密钥、原始异常或operationId。没有真实凭据端口时仍拒绝敏感配置，不用这批工作替代凭据安全验收。

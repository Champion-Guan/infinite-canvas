# 历史列表虚拟化验收

日期：2026-11-06。目标：降低 MacBook Air M1 8GB 在历史记录增多时的展示开销，保留完整历史、原生滚动、键盘导航和跨屏操作。

## 修改范围

原侧栏历史、总览任务列表、总览已选详情均直接遍历并挂载全部内容。详情虽有屏外原图延迟读取，仍保留全部详情节点。

本轮三个入口统一接入 `历史虚拟列表.tsx`：

- 侧栏只渲染可见行和上下缓冲，状态信息、预览、勾选、失败重试入口保持原语义。
- 总览任务按文件拆行，一个任务包含大量图片时也不会一次挂载整批文件。任务标题和单图分组外观保留。
- 已选详情按响应式网格分行虚拟化，只保留一行上下缓冲；单张、双张选择不会留下空列，图片使用原有可用宽度。

使用 TanStack Virtual 处理动态行高、可见范围和尺寸测量。依赖版本固定为 react-virtual 3.14.22、virtual-core 3.19.7；沿用已有依赖封装方式，将浏览器 ESM 入口构建为 35,413 字节的依赖模块，保留 MIT 许可，并外置 React / React DOM，复用工作台已有实例。构建命令为 `node 开发工具/构建历史虚拟列表依赖.mjs`。

原生滚动不增加等待动画。控件动效和小列表排序动效保留，虚拟行重新进入视区不重复播放详情入场动画。宽度变化、换行和图片加载通过尺寸测量更新排布。

勾选和下载仍使用完整文件清单和稳定文件 ID；虚拟化不截断历史数据。焦点行及其相邻行在键盘操作期间保留。详情提示词的展开状态移至总览所有者，虚拟行卸载后再进入仍保持展开。

总览按已选文件预先汇总每个任务的勾选数量，滚动时不在每个文件行重复统计整批文件。

## 自动检查

`开发工具/历史列表虚拟化.test.mjs` 使用实际 React 和打包后的虚拟引擎，覆盖：

- 一万条历史的 SSR 首屏输出不超过 20 条；恢复中间及末尾位置不超过 24 条，末尾可达。
- 动态行高变大后不重叠；排序继续使用稳定记录 ID。
- 焦点行和相邻行保留，支持连续 Tab。
- 宽、窄网格分组不丢尾部文件；一万条已选文件的 SSR 初始详情只渲染可见行和一行缓冲。
- 一个任务包含一万张图片时按文件虚拟化，而非在一个虚拟行内挂载一万张图片。
- 空任务、单张文件、原始文件身份保持。
- 直接按原生 ESM 加载依赖产物，防止将 Node 可用的 CommonJS require 误带入浏览器。

历史选择、下载 ZIP 内容、屏外媒体释放、排序、重试与图片详情的定向检查共 45 项，全部通过。

完整回归：123 个文件，1221 项检查，1220 项通过、0 失败、1 项跳过（缺少真实 HEIC 文件）。源码映射检查 627 文件、1987 引用、368 顺序补丁通过；完整 TypeScript 检查通过；用户体验检查 250 个 React 模块、793 个 JavaScript 模块，无问题。

## 边界

挂载数量随视区高度、实际行高、网格列数和键盘焦点变化，不是固定条数上限。完整历史及下载清单仍留在数据层；本轮减少展示节点与屏外预览资源，不改变存储格式。

一万条场景验证的是实际 React SSR 输出与虚拟引擎行为；实页使用现有 13 条图片历史。没有将一万条合成记录写入用户工作区，也没有测量浏览器长列表的帧率或峰值内存，不能据此宣称整个项目在所有负载下均保持固定帧率。

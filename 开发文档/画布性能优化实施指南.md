# 画布性能优化实施指南

## 概述

针对用户反馈的"169 个卡片时画布拖动和缩放卡顿，加载速度慢"问题，实施快速性能优化方案。

## 优化策略

### 核心思路：拖动时降级渲染

在用户拖动画布或调整节点大小时，将可见节点从完整渲染（30+ props，复杂 UI）降级为简化渲染（仅边框 + 缩略图）。

### 技术实现

1. **SimplifiedCanvasNode 组件**
   - 只渲染节点边框、背景和基础内容
   - 无交互元素（按钮、面板、端点等）
   - pointerEvents: none（不参与鼠标事件）
   
2. **渲染条件判断**
   ```tsx
   const shouldSimplify = (isCanvasPanning || isNodeResizing) &&
                         visibleNodeIds.has(node.id) &&
                         mountedVisibleNodes.has(node.id) &&
                         !hasDeferredCanvasMedia(node);
   ```

3. **三级渲染策略**
   - **简化渲染**：拖动/缩放中的可见节点
   - **占位符渲染**：未挂载或媒体延迟加载的节点
   - **完整渲染**：正常状态下的节点

## 测试验证

### 性能测试

1. **测试场景**
   - 169 个节点的画布
   - 快速拖动画布
   - 缩放操作
   - 调整节点大小

2. **验证指标**
   - 拖动帧率：目标 40+ FPS（优化前 15-20 FPS）
   - 响应延迟：目标 < 100ms
   - DOM 节点渲染：拖动时只渲染简化版

3. **验证方法**
   ```tsx

       }

   ```

## 后续优化（可选）

如果快速优化后仍有性能问题，可以继续实施：

### 阶段 2：深度优化
1. **更激进的虚拟化**
   - 离开视区 5 秒后卸载节点
   - 减少驻留节点数量

2. **React.memo 优化**
   - 为 CanvasNode 添加 memo
   - 减少不必要的重渲染

3. **拖动时隐藏连线**
   - 连线渲染开销较大
   - 拖动时可以临时隐藏

### 阶段 3：长期优化
1. Canvas 2D 连线渲染
2. Web Worker 计算可见性
3. 虚拟滚动优化

## 风险评估

### 低风险 ✅
- 简化渲染只在拖动/缩放时生效
- 不影响正常状态下的功能
- 可以随时回滚

### 需要注意的点
1. **指针事件**：简化节点设置了 `pointerEvents: none`，确保不会干扰正常交互
2. **选中状态**：简化节点正确显示选中边框
3. **过渡平滑**：从简化渲染切换到完整渲染应该平滑

## 回滚方案

如果优化导致问题，删除以下代码即可回滚：

1. 删除导入语句：
   ```tsx
   import { SimplifiedCanvasNode } from "@/上游适配/简化节点渲染补丁";
   ```

2. 恢复原节点渲染代码（去掉 `shouldSimplify` 判断）

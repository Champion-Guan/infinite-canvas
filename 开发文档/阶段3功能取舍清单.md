# 阶段 3：功能取舍与迁回清单

本文件是供用户审查的建议清单，不是删除授权，也不是功能已经接入的声明。目标仅为 Web 工作台，不开发 SwiftUI、AppKit、Electron、Tauri 桌面产品；macOS 快捷入口、Keychain 和用户态服务属于 Web 项目的本机运行辅助。

2026-10-15：用户已在 [原作者功能全量清单与取舍表](原作者功能全量清单与取舍表.md) 选择32项关闭，并单独批准具体差异，现已接入3100；状态和限制见 [阶段5功能关闭验收](阶段5功能关闭验收.md)。下文K/M/D是此前建议和迁入规划，冲突时以用户最新选择为准，不能据K08擅自重新开放原版插件。纠正K06：原版本地放大已有实现，但AI超分只是“尚未实现”的占位，不应称为已可用的超分工具。

## 判断规则

- **保留原版**：复用作者 UI 和交互，不移植旧版对应大文件。
- **需要迁回**：根据用户既有要求保留业务价值，但重新按模块接入，不照搬旧实现。
- **暂缓接入**：当前客户场景不优先，不加载到 Guan 主产品；原版源码和旧版数据保留。未来取舍另行确认。
- **不再沿用旧实现**：舍弃旧架构方式，不是删除旧项目或备份。
- 当前 `localhost:3100` 已运行获批的功能关闭副本，统一策略实际接入路由、控件及执行边界；作者原仓库仍完整保留。自有产品业务尚未迁入。

接入分类：A = 直接复用原版；B = 真实节点插件；C = 需审查批准的最小应用接入；D = 自有本地服务/运行工具。优先级先保证身份、保存和凭据安全，再推进客户功能。

## 4. 不再沿用的旧实现方式

## 5. 依赖与资源决策

原作者依赖不在本阶段删除。React/Router/Zustand/localForage/Ant Design/Tailwind、节点 SDK、图片/ZIP 存储共享服务继续保留。新插件不能打包第二套 React，不能复制旧 node_modules、密钥配置或旧发布产物。

旧 Excel vendor 通过服务器注入 `xlsx.full.min.js?sheetjs-local-0.18.5`，压缩库注入标识为 fflate 0.8.3。后续采用有明确来源、许可、锁文件和安全审查的独立解析依赖，不把现有 vendor 文件当作已安全审查通过；本阶段不安装、升级或删除这些依赖。

## 审查结论

建议首先审查 M01–M05 的业务含义与第 3 节暂缓项。通过后开始小范围插件验证，再引入应用接入槽位。所有 C 类都需要说明具体接入文件、最小差异和测试；本清单不是对未知核心补丁的总授权。

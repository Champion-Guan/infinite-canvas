# 历史图片并发重试验收

日期：2026-10-31。维护位置：根目录扩展功能及上游适配。没有发起真实生图，没有推送或发布。

## 修改

- `扩展功能/生成历史/历史失败重试.js`：先按节点、图片槽位去重并读取当前状态，图片使用 Promise.allSettled 并行启动；同步抛错也不会截断其他图片。启动时再次检查页面活动、目标存在、失败状态和不可用素材标识。视频等其他类型仍逐项重试。
- `扩展功能/画布生成/图片重试门控.ts`：图片槽位独占自身，整卡重试独占节点，准备异步参考图后重新检查；完成时根据剩余槽位恢复节点状态。
- `扩展功能/画布生成/并发生成状态.ts`：请求登记支持可选槽位键，真实 targetNodeId 和 runningNodeId 不变；整节点取消清理所有对应槽位，旧请求结束不删除新请求。
- `上游适配/历史图片槽位并发重试接入.patch`：接入主入口 handleRetryNode。生成任务ID、确认、保存流程继续使用既有实现。
- 源码映射更新；`开发工具/历史图片并发重试.test.mjs` 已加入 `test:concurrent-generation`。

## 已验证

- `npm run test:concurrent-generation`：71 项通过，包括 6 项历史并发专项。
- 7 张失败图片在任何响应完成前全部进入 onRetry。
- 同节点不同图片槽位并行，同槽位与整卡重试互斥。
- 单项同步、异步失败不阻止其他图片；等待所有任务完成才结束重试组。
- 缺失、成功、目标本身 loading 的图片跳过；不可用素材仅在 storageKey 仍匹配时重试。
- 页面失活后未启动项不发起；整节点取消按真实节点找到并中止全部槽位。
- 视频等非生图历史重试继续逐项启动。
- 真实 handleRetryNode 回调通过本地 mock 执行，未访问上游。
- 额外的批量保存竞态和生成历史总览测试：21 项通过。
- `npm run dev:check-source`：542 个文件一致、1617 个引用、270 个有序接入补丁。
- `npm run dev:restart`：新构建时间 2026-10-31T15:29:32.065Z，PID 97801，localhost:3000，HTTP 200，既有工作区ID未变。

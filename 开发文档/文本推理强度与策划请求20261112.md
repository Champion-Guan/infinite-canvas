# 文本推理强度与策划请求

日期：2026-11-12。范围：当前开发版，未发布新客户安装包，未提交收费模型请求。

## 原因

原默认推理强度为`auto`，OpenAI兼容Responses请求遇到此值时省略`reasoning.effort`。“AI写提示词”读取全局文本配置，不读取某张文本卡的独立强度。因此，文字卡中调整强度不会自动应用到商品策划，截图中渠道记录为“-”不能单独证明模型服务的实际内部推理方式。

## 调整

- 按用户最后给定截图，文本选项统一为“无推理 / 轻度 / 中 / 高 / 极高 / Max”，移除“自动”和Ultra，默认值为`medium`。旧配置的`auto`、已移除的`ultra`、缺省或无效偏好按“中”读取，有效的用户选择继续保留。旧任务原始请求快照不重写。
- “设置 → 偏好设置 → 默认文本模型”的模型列表内，悬停模型名称展开推理强度二级菜单，同时保存模型和强度，不再单独放置默认强度表单。“AI写提示词”、优化和翻译等未单独指定强度的文本任务读取此值。
- 文本生成配置卡的模型选择器使用同一二级菜单，同时保存该卡的模型和强度；文本卡按用户要求保留原模型框和独立的六档设置，不接入二级菜单。
- 用户最后追加要求：文本卡与生成配置卡的独立“文本设置”面板均固定显示“无推理 / 轻度 / 中 / 高 / 极高 / Max”；`gpt-6.1-sol`、`gpt-6-astra`的“无推理”灰显禁用。只改变独立面板的显示，模型选择器二级菜单仍隐藏这两个ID的“无推理”；实际支持校验不放宽。
- 二级菜单文字靠左、选中钩靠右。两个面板顶边对齐，中间保留间隙，分别按内容自然撑开，不以固定高度补齐空白；模型较多时限制视区高度并滚动。
- OpenAI兼容Responses请求明确传递`reasoning.effort`。沿用原任务身份、结果恢复和保存确认流程，不为改设置重发已有任务。
- 支持能力按完整模型ID精确匹配：`gpt-6.1-sol`、`gpt-6-astra`支持轻度至Max，按用户最后修订直接隐藏“无推理”；`gpt-6.1-terra`、`gpt-6-luna`支持含“无推理”的全部六档。已知ID的禁止档位不能由渠道配置重新开启。
- 不以Sol/Astra名称片段、前缀或相似ID推断支持；`gpt-6-sol`、带供应商前缀或额外后缀的ID均不套用上述规则。未知ID未配置列表时沿用轻度、中、高、极高四档，可在“渠道 → 编辑 → 文本模型 → 支持的推理强度”按真实渠道能力声明。已知ID允许渠道进一步收窄；不同渠道同名模型不借用配置。这些规则来自用户截图与明确要求，不是通过收费请求探测或自动认证的能力。
- UI禁用未声明的档位，请求编码再次校验；旧配置选中不支持的档位时，在渠道绑定、任务登记和提交前报错，不静默降档。
- 配置导入导出及冷读取保留模型支持列表，未知档位和错误类型继续拒绝。Gemini原消息协议保持，本轮未新增其原生thinking参数映射。

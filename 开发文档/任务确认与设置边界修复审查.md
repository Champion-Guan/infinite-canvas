## 问题与行为

上一轮任务 `4e0bc0d2-0272-423b-82c4-27815fdf7f1a` 的图片和响应收据已保存，但 `applied:false`。原调用在保存 ACK、checkpoint 或 applied 任一步失败后退出；后续点击本机保存重试只恢复存储队列，不会恢复已退出的确认调用。卡片已有图片时状态保持 success，普通图片重试按钮也不再出现。这里已确认恢复入口缺失；没有凭历史快照推断当时究竟是哪一次确认请求先失败，也没有修改历史账本使验收变绿。

候选在原画布挂载独立的任务确认状态组件。仅发现原图片卡片上相互匹配的任务记录和收据，先取原产品任务清单；已完成确认的任务跳过。未确认项先通过原产品真实 React 提交票据和 SQLite ACK 保存，再以原任务 ID 查询、取得后端检查点并确认完成。收到本机保存恢复事件会继续确认；仍失败则保留“重试任务确认”按钮。此入口没有 submit、bind、result、媒体写入或新任务 ID 操作。

另有可重复的并发窗口：旧版产品串行锁在 checkpoint 返回时即释放，applied 请求仍在锁外。下一张图片可以提前推进同产品画布版本，导致旧检查点失效。专项测试分别复现旧顺序并验证候选把锁保持到 applied 响应返回；跨产品仍使用各自队列。后台仍严格验证产品、节点、响应摘要和已保存根版本，没有放宽验证器。

设置主弹窗的旧来源位于 84px 顶栏下方的 iframe，`72vh` 以该画布视区计算。候选把设置主弹窗从顶栏组件移入真实的 React 视区容器，通过 Ant Design 的 `getContainer` 和 `styles.root/wrapper/mask` 公开接口约束遮罩、居中区域；body 的 `72cqh` 继承视区高度。保留 980px 宽度、页签、内容、文案及原交互；独立全页调用仍使用 `72vh`。没有查询、改写作者 DOM 或注入全局样式。

# M1 逐项资源优化与验收

日期：2026-11-02，Asia/Shanghai。

环境：本机 MacBookAir10,1 / Apple M1 / 8GiB / arm64，现有开发服务 http://localhost:3000。依据根目录《MacBook_Air_M1_优化审查报告.md》逐项复核，沿用 M01–M27 编号。原报告日期为 2024-11-01，本次执行日期另列，不将原文估算当作实测。

## 本次实际修复

+ [优化] 隐藏产品卸下画布节点、连线和侧栏图片，返回产品再按视区恢复；后台生成、保存与历史操作的拥有者继续挂载。
+ [优化] 画布节点列表、生成历史及历史总览改为接近视区才读取缩略图，避免列表初始化就解码全部原图。
+ [优化] 派生缩略图内存缓存采用 LRU，最多 128 条且字符串预算 8MiB；单条超预算可以显示但不常驻。已显示的图片不因缓存淘汰失效。
+ [修复] 同一缩略图的并发读取共用一份请求；40 次同时恢复由 40 次存储读取降至 1 次。
+ [修复] 删除图片后，迟到的缩略图读取、编码和解码结果不能复活缓存或重写预览记录；预览失败降级，下一次仍可重试。
+ [修复] 缩略图绘制和编码异常时同样关闭 ImageBitmap，并清零临时 Canvas 的像素缓冲；正常编码前先释放原始位图，降低峰值。
+ [文档] 修正上一轮 M16/M17 未覆盖隐藏产品和派生缓存的结论；补齐真实浏览器观察与资源生命周期回归。

仅对可重新生成的缩略图做淘汰。应用状态/偏好 Map 是同步接口所需的数据镜像，原图地址可能仍被节点与历史引用，不能当垃圾缓存盲目删除。缓存字符串预算也不等于浏览器总内存上限。

## 真实页面观察

同一未命名产品3、87 节点、约 78% 缩放，使用已有数据和同一浏览器页面：

| 状态 | 实际挂载节点 | 带 src 图片 | 观察 |
| --- | ---: | ---: | --- |
| 修前切走后的隐藏产品 | 22 | 49 | 仍持有画布及侧栏展示 |
| 修后切走后的隐藏产品 | 0 | 0 | 画布与历史页两条路径均验证 |
| 修后返回原产品 | 22 | 15 | 87 节点、78% 缩放、已保存恢复，无已完成的破图 |

修前/修后该画布 DOM 中去重图片的 `naturalWidth * naturalHeight * 4` 合计由 120,001,028 降到 36,920,324 字节。这仅是像素展开量估算，不是进程 RSS、JS 堆或实际释放内存的测量，不能据此声称整机内存下降 69%。

生成历史进入选择模式后取消主图-1的勾选，切走产品再返回，主图-1仍未勾选、详情页01-1仍已勾选。隐藏产品没有图片节点；返回后列表正常显示。查看主图-1的详情，实际加载图片为 900×1200，与最终尺寸一致，详情关闭可返回。

平移从 `translate(-30.8537px,108.26px)` 改到 `(49.1463px,138.26px)`，界面显示保存中后回到已保存；刷新当前页面恢复相同位置、缩放及 87 节点。验收结束还原原位置。本轮未用真实关闭浏览器来覆盖防抖期内退出的场景，该边界由退出/ACK 故障测试覆盖。

# 阶段 3：外挂式接入方案

本文件是设计方案，不是已实现接口。基于锁定的原作者 v0.20.0，以及旧项目当前工作区源码。业务范围见 [功能取舍清单](阶段3功能取舍清单.md)，实施门禁见 [分批开发与验收计划](阶段3分批开发与验收计划.md)。

## 1. 结构与基本边界

```text
原作者 Git 仓库（只读、完整历史）
            │ 锁定提交、生成副本
            ▼
Guan二次开发/.运行/<上游提交>/（可删除重建的运行产物）
            ▲
            │ 构建自有插件；仅应用明确批准的适配
Guan二次开发/
├── 扩展功能/   自有领域规则、节点插件、产品界面、本机服务
├── 上游适配/   SDK 映射、受审查接入补丁、兼容性检查
├── 界面资源/   自有品牌、插图、局部样式与动画规范
├── 开发工具/   准备、构建、测试、保护与未来发布工具
└── 开发文档/   接口边界、审批、验收与同步记录
```

只复用确实需要的能力，不提前建“万能桥接框架”。自有业务不依赖作者组件内部 DOM、CSS 类名、MutationObserver 或 iframe 重排。原作者节点、连线、主题、工具栏与公共组件是保留对象，不整文件替换。

新开发Origin仍为 `http://localhost:3100`，不自动换端口；旧3000/8888/5174的数据、Chrome配置、Keychain与运行服务不接入。正式版已规划在阶段6完成本机持久化后，阶段10实现默认3000、占用顺延3001/3002和实例复用。顺延依赖已授权的同一本机数据根，不是浏览器数据跨Origin自动共享；旧数据迁入仍在阶段11单独验收。

## 2. 哪些是真实插件，哪些不是

下表上游路径均相对 `../infinite-canvas-upstream`。

| 已存在的协议 | 源码 | 本项目可以如何使用 |
| --- | --- | --- |
| `CanvasPlugin.nodes`、`setup`、插件 CSS | `web/src/types/canvas-plugin.ts`、`plugins/canvas/sdk/src/types.ts` | 注册自有参数节点、导入节点与其面板；CSS 仅作用自有节点/面板，不覆盖全局弹层 |
| `Content`、`Panel`、`toolbar`、`resource`、`openPanel` | 同上；`web/src/lib/canvas/plugin-node-context.ts` | 参数编辑、解析预览、最终提示词输出；通过 `resource` 提供下游文本 |
| `getNodes/getConnections/getUpstream/getDownstream`、`updateMetadata/updateNode` | 同上 | 读取当前画布和更新自有节点；不能据此读取任意非当前产品 |
| `applyOps` | `web/src/lib/canvas/canvas-agent-ops.ts`、`web/src/pages/canvas/hooks/use-plugin-host.tsx` | 创建节点、连线等指令；类型返回 `void`，不代表持久化完成或数据库原子事务 |
| `ctx.ai.generateImage/Text/Video` | `web/src/pages/canvas/hooks/use-plugin-host.tsx` | 原版模型能力；新插件原型只模拟调用，不填写真实密钥 |
| `ctx.storage`、`emit/on` | `web/src/lib/canvas/canvas-event-bus.ts` | 插件私有状态与事件；命名空间按插件 ID，不自动按产品隔离，也不是安全沙箱 |
| URL 安装、开发插件、本地插件发现 | `web/src/lib/canvas/plugin-loader.ts` | 加载自己构建的插件，使用现有 `VITE_DEV_PLUGINS` 或本地清单 |

当前协议**不提供**全局路由注册、顶部产品胶囊槽位、设置页槽位、工作簿归属、当前产品 ID、后台任务持久化确认或原图/最终图 Blob 管理。`generateImage` 当前仅返回 `{ images: string[] }`，不能承诺插件独立拿到尺寸来源与两份交付文件。

因此：M01/M04/M05 的节点原型可以优先使用真实 SDK；M02/M03/M07/M09/M13/M18 等应用能力必须单独审查接入口。未批准前不编造协议、发明未被宿主处理的事件名来宣称功能已接通。

## 3. 先独立领域数据，再接 UI

建议第一批建立以下概念，字段和格式在 7-1 实施时定稿，并配有 schema 版本和测试。

```text
工作簿 workbookId
└── 工作表 sheetId
    └── 产品 productId
        ├── 画布 projectId（首轮一产品对应一画布）
        ├── 参数 parameterSet
        └── 任务 taskId → 结果 resultId → 媒体 mediaId
```

- 手工新建产品不伪造 Excel 来源；没有工作簿时归入明确的“未关联”分组。
- 工作簿、工作表、产品与画布均使用稳定 ID。文件名、工作表名、产品标题可以修改，不能当主键。同名文件再导入时明确区分新增与用户确认的更新。
- 工作簿/工作表保存各自的当前产品选择；切换工作表只显示该工作表的产品。产品名称生成规则独立测试为“未命名产品1、2、3…”。
- 解析规则输入为显式的表格行、列与产品参数；输出是规范化记录、警告、主题依据和变量绑定建议。不读取 `window.__guanExcelPromptContext` 或 URL 中的产品名。
- 变量绑定区分“缺失”“显式清空”和“有值”；尺寸展示优先绑定经核对的尺寸，不能把核心卖点强塞进尺寸主题。AI 只产生可审阅建议，失败不覆盖确定性解析或用户编辑。
- 节点 metadata 可带自有的版本化 `guan` 数据，记录 `productId`、导入行 ID、规则版本与用户修改标记；避免给所有原作者内置类型强加新必填字段。
- 第一批领域测试不读旧业务数据库。后续旧数据导入由专门的备份、校验和恢复工具负责，不搬旧版隐式“补归属”迁移逻辑。

### 存储职责

本表区分原版现状与产品目标。阶段6先在新测试数据根实现并验收本机数据库、媒体目录和受限Node.js服务；数据库选型待审查。以下目标尚未实现，不能把原版 `ctx.storage` 或画布仓库称为本机数据库接口。

| 数据 | 原版现状或可用协议 | 阶段6后的目标责任与限制 |
| --- | --- | --- |
| 画布节点、连线、视口 | 原版浏览器画布仓库；`CanvasProject` 位于 `web/src/stores/canvas/use-canvas-store.ts`，无工作簿字段 | 经批准的持久化适配写入本机数据库；原版交互与内存状态保留，持久化完成必须有确认 |
| 工作簿/工作表/产品映射、规则配置 | 原版没有此业务契约 | 自有版本化本机数据库；工作区身份不依赖端口，浏览器仅缓存 |
| 参数节点的持久偏好与metadata | 插件 `storage` 是插件ID命名空间的浏览器存储，非安全沙箱 | 重要偏好和节点业务数据用本机契约；插件storage仅保存可重建状态；禁用/卸载不默认删除业务数据 |
| 图片原图、最终图与来源元数据 | 原版媒体接口没有两份交付文件的完整协议 | 文件放本机媒体目录，元数据/引用放数据库；两份文件独立保存、校验，不覆盖原图 |
| 任务状态、历史、幂等提交记录 | 需自有任务模块，原版applyOps没有持久化ACK | 本机数据库记录；暂存媒体、提交、确认和失败恢复显式协调，不假设跨文件事务天然存在 |
| 密钥、代理认证 | 原版仍浏览器保存密钥并前端直连API | 阶段7-4独立测试Keychain/后端网关，前端仅不透明引用；真实凭据另行授权，不能以普通文件明文存放 |

数据根与代码/版本目录分开，并按用户及工作区隔离；当前阶段不创建生产目录、不接旧数据。阶段6必须验证重启、并发、空间不足、备份恢复和跨测试Origin授权读取。精确Origin、Host、会话、CSRF及路径访问控制是基础条件；不能用 `Access-Control-Allow-Origin: *` 支持端口顺延。真实旧浏览器数据迁入阶段11先备份再复制，核对条数、哈希及媒体引用，验证前不删除旧副本。

原版删除画布时只保留 `{ id, deletedAt }` 墓碑，不是完整恢复副本。Guan 回收站必须在删除前保留必要快照与媒体引用，不能把原版墓碑解释成已支持恢复。

## 4. 节点插件的构建与接入

未来参数节点沿用自有类型 `guan:prompt-variables`，通过 SDK 注册，不修改 `nodes/builtin-nodes.tsx`。旧 `prompt-variables-node.tsx` 只作为功能/规则参考；从中提取纯解析与绑定，UI 使用当前作者主题和面板契约重新接入。

构建必须复用宿主 React 单例。SDK `runtime` 和 automatic JSX 已提供宿主能力，不能把另一套 React/ReactDOM 打包进插件。自有包的依赖和锁文件独立，不改作者依赖锁。

作者 `plugins/canvas/sdk/build.mjs` 的真实行为：默认生成插件根目录 `dist`，再复制到向上三层推导出的 `web/public/plugins`。未来可显式指定 `publicDir` 到运行副本，并使自有 `dist` 被忽略；或者用自有构建入口直接生成 `.运行/` 产物。**不能在原作者目录运行默认构建，也不能只覆盖 `outfile` 却忽略同步插件仍读取默认 dist 的行为。**

插件 CSS 必须带自有根标识；不选择 `.ant-modal`、全部按钮或全部画布节点来施加共享 transform。事件订阅、样式、计时器在禁用/卸载时清理；持久化数据是否删除另行征询用户。

## 5. 必要的应用接入口：拟议，不是现成 API

以下是候选边界。正式编码前逐批提交具体 diff，说明改动位置与原因；表格不是任意修改核心的总授权。

| 接入口 | 候选上游接入位置 | 自有能力 | 验收重点 |
| --- | --- | --- | --- |
| 产品工作区与画布生命周期 | `web/src/pages/canvas/project.tsx`、`web/src/stores/canvas/use-canvas-store.ts` | 当前产品/画布身份、切换前保存确认、保留视口、非当前产品结果提交 | 必须区分“打开的画布”与“结果归属画布”；仅仅换路由不够 |
| 顶栏、空白页、设置槽位及产品配置 | `web/src/components/canvas/canvas-top-bar.tsx`、`web/src/components/layout/app-config-modal.tsx`、`web/src/router.tsx`、初始化入口 | 产品导航、导入、Guan 品牌、版本、选择性入口 | 隐藏入口不等于停掉后台逻辑；不破坏作者组件/标识 |
| 生成与凭据门面 | `web/src/pages/canvas/hooks/use-plugin-host.tsx`、`web/src/services/api/`、配置初始化/仓库 | 自有安全网关、任务身份、错误映射 | 内置生成与插件生成均覆盖，不能只保护一个按钮 |
| 媒体、详情、内容导入及资产拖放 | 项目页、`web/src/services/image-storage.ts`、`web/src/components/canvas/canvas-side-panel.tsx` | 原图/交付图、结果来源、媒体导入、拖放载荷 | 原图与最终图不混用，失败不残留半批节点 |
| 性能热路径 | `web/src/components/canvas/infinite-canvas.tsx`、`canvas-connections.tsx` 等 | 测量证实后才提出局部调度/可见性方案 | 不先复制旧“优化版”，不动画化逐帧位置 |

先用小而明确的端口函数，例如“获取当前身份”“向指定 projectId 提交结果”“确认持久化”，由自有模块定义版本；在最少的宿主位置接入。不做全局事件总线承载所有状态，也不以可执行字符串替代类型化接口。

普通本地页面没有真正的插件安全沙箱。批准接入口后仍需供应链审查；第一版只加载审核过的插件，不开放任意 JS/URL 插件和自定义脚本给客户。

## 6. 产品切换、任务与媒体必须同一套归属

拟议流程：

1. 用户生成时创建不可变任务上下文：`taskId/productId/projectId/sourceNodeId/credentialRef`，捕获当次参数和引用媒体。
2. 界面可以切换产品；任务执行不依赖旧页面是否仍 mounted，不读取变化后的“当前产品”决定结果归属。
3. 结果先准备原图、交付图和元数据；校验目标产品状态及源节点是否仍存在，再幂等提交到指定画布。已删产品、源节点或取消任务有明确处理，不错误写到当前产品。
4. 成功提交后再确认完成；刷新、断网、重复回调只提交一次。保存中的状态不会被动画完成事件冒充持久化完成。
5. 创建结果卡片时才运行水平排布/避让。连线磁吸、选择与人工拖动不触发自动布局；不能全局包装每个 `setNodes`。

原版 `applyOps` 没有提交 ACK；现有项目页也有自己的局部状态和异步保存，因此跨产品提交必须做版本冲突与写入协调测试。不能仅调用原版 `updateProject` 就断言当前页面不会把旧状态写回。

ZIP 内容导入先构造完整计划：节点/连线/媒体 ID 重映射、引用校验、活动任务标记清除、资源暂存；再提交与确认。`applyOps` 一次传入数组不代表 IndexedDB 和媒体写入已经原子化。失败应回收本次暂存并恢复快照，不能删已有文件。

## 7. 密钥与网络安全边界

原版目前仍在浏览器保存 API Key，并由前端调用 API。`web/src/components/layout/client-root-init.tsx` 还会读取 URL 的 `apiKey/baseUrl` 导入渠道；事后移除参数不保证浏览器历史、粘贴或日志中从未出现。

计划在 7-4 建立独立本机网关，并通过审查后的适配统一接管所有启用的生成入口：

- macOS Keychain 使用新测试服务标识；前端仅显示渠道、模型与不透明 credentialRef，不读回密钥。
- 本地请求检查允许的 Origin、会话授权与 CSRF；不得仅相信“来自 localhost”，也不得提供任意系统命令接口。
- 外部请求绑定审核过的提供方、地址和能力；防止任意 URL/内网访问、跨来源重定向携带认证头，以及密钥出现在 URL 或错误日志。
- 支持合法自定义渠道的策略在实施时明确，未验证地址不静默放行。代理路由与认证独立，软件更新网络也不能与生图状态绑定。
- 日志脱敏、无凭据返回、前端 bundle/IndexedDB/localStorage/控制台检查通过后，才允许用户单独授权真实 API 测试。
- 任意脚本在同源页面运行仍可滥用已经授权的请求，Keychain 不等于沙箱。未经额外安全方案不承诺兼容所有脚本。

阶段 3 没有实施此网关。测试环境继续只用模拟数据；不得把“目录隔离”和“浏览器密钥安全”混为一谈。

## 8. 最小适配的保护与上游更新

批准后的补丁只存 `上游适配/` 并作用于 `.运行/`。每份补丁应记录：目的、批准记录、锁定上游提交、精确源文件 SHA-256、预期差异、产物哈希、接口版本、对应测试、撤销方法。

- 生成前确认作者仓库干净且与基线一致。
- 接入脚本核对路径、源文件哈希与补丁上下文；不接受模糊匹配，不兼容即停止。
- 记录运行副本相对上游的完整差异清单，除声明的补丁和自有构建产物外不得出现其他变化。
- 失败回退到上一个已验收提交及其副本；回退代码不覆盖私人数据。新存储格式另有版本门禁，不能盲用旧程序读取新数据。
- 作者增加正式接口后优先移除相应补丁，切换到真实协议；Git 同步成功与适配通过分别验收。

更新流程继续按 [架构与开发顺序](架构与开发顺序.md)：fetch → 审查 → 新基线副本 → 原版测试 → Guan 合约和业务回归 → 合入自有分支。原版源码保持原作者提交，Guan 历史独立；不把旧仓库无关历史强行合并到作者仓库。

```text
                   受限本机数据API
                         │ 提交成功才返回ACK
                         ▼
                SQLite索引 + 独立媒体文件
```

- `扩展功能/扩展边界/存储端口.mjs`：`guan-extension-storage.v1`，为审核过的自有模块提供固定命名空间，只暴露业务记录读写。模块不能通过这个端口提交SQL、路径或命令。
- `扩展功能/本机存储/浏览器适配.mjs`：校验文档、媒体哈希、保存ACK；报告`saving/saved/error`。读到旧文档不能抹去失败的保存；没有静默localStorage/IndexedDB降级。
- `扩展功能/本机存储/协议.mjs`：`guan-local-data.v1`，集合仅`canvas/extension`。阶段7的工作簿、产品、任务等需定义自己的版本化文档，不能把一个通用JSON表说成这些业务都已实现。
- `扩展功能/本机服务/数据服务.mjs`：Node专用边界；自有业务、浏览器端不直接访问数据库。
- `扩展功能/本机存储/SQLite工作区.mjs`：Node专用边界；不导入React、Zustand、原作者内部路径或运行副本。

这里是可维护性和能力约束，**不是恶意同源JS沙箱**。任意脚本仍能滥用所在页面已获授权的能力；关闭的任意插件、Agent、自定义脚本不会因此重新启用。

## 数据位置与内容

没有默认生产数据路径。`openWorkspace`必须显式传入独立绝对数据根，只有`initialize:true`允许首次创建；未知非空目录不能接管。测试全部用系统临时目录中`mkdtemp`创建的全新根，具体路径记录在验收日志。

```text
<新数据根>/
├── .工作区.json          协议、schema、稳定工作区UUID
├── .实例锁.json          单实例保护，不强杀进程、不自动清除残留锁
├── 工作台.sqlite         文档、修订号、媒体索引/引用、幂等ACK
├── 工作台.sqlite-wal     SQLite管理的提交日志（运行时可能存在）
├── 工作台.sqlite-shm     SQLite管理的共享内存索引（可能存在）
├── 媒体/<SHA-256>        实际媒体，内容寻址，不接受客户端路径
└── 备份/<UUID>/          数据库快照、全部索引媒体、清单
```

目录0700、托管文件0600。拒绝根/文件符号链接、文件硬链接、其他用户可写的托管路径，以及代码目录和旧项目目录；系统`/var`链接先规范化。文件权限不是加密，也不防同一账户/管理员/磁盘损坏。

未来正式候选：`~/Library/Application Support/AI-Workbench/<工作区ID>/`。**当前未创建此生产目录，也未复制旧数据。** 当前3100依然使用作者浏览器仓库，旧浏览器数据迁入必须留在阶段11。

SQLite表：`workspace`（身份）、`documents`（JSON/版本/哈希）、`media`（大小/MIME/哈希）、`document_media`（外键引用）、`operations`（幂等请求哈希和ACK）。本轮不实现删除、回收站、垃圾回收或自动schema迁移。

## 保存、冲突与媒体

1. 上传媒体：校验类型/体积，SHA-256去重；暂存文件写入并fsync后原子落位，目录同步，再记录数据库索引。索引失败时保留孤儿文件，不报告成功、不删除其他文件。
2. 保存文档：必须带`expectedRevision`、唯一`operationId`、显式`mediaIds`；校验节点/连线引用、媒体存在及哈希。
3. `BEGIN IMMEDIATE`内检查预期版本，更新文档/媒体引用/幂等记录，`COMMIT`成功才返回`persisted:true`。WAL + `synchronous=FULL`，不把发出请求或动画结束当成功。
4. 同一操作同一请求重复提交返回原ACK；复用操作ID但改内容拒绝。提交成功却响应丢失时，调用方必须用原操作ID和相同内容重试。不能自动生成新ID覆盖。
5. 冲突、磁盘空间不足、未知schema、媒体损坏都安全停止；浏览器保留未确认状态，不能拿旧数据当空库重新覆盖。

`blob:`临时URL不是文件身份。画布节点的`metadata.storageKey`必须改成已声明的`media:<hash>`，不能直接传原作者`image:<id>`。浏览器适配返回Blob而不缓存objectURL；后续UI负责创建/撤销展示URL。原图与最终图可以保存成两个不同媒体ID，但两份交付的具体业务尚未迁入。

阶段6上限：单文档2MiB、单媒体32MiB、嵌套40层；列表最多1000条，超限明确报错而不是静默漏项。它们是当前验收边界，不是客户最终大项目/长视频能力。节点ID兼容nanoid的字母、数字、`_`和`-`。画布内容中未知的普通JSON字段保留，不静默剔除。

## 本机接口与授权

服务只监听`127.0.0.1`，测试动态端口`0`由系统分配，不占用3000/3100。精确Host检查防止DNS rebinding；Origin逐个白名单，不允许`*`或`null`。

| 方法与路径 | 作用 |
| --- | --- |
| `GET /health` | 已授权会话核对协议/工作区，无磁盘路径 |
| `GET /v1/workspaces/<UUID>/documents/<集合>` | 限量文档索引 |
| `GET /v1/workspaces/<UUID>/documents/<集合>/<ID>` | 文档、版本、哈希、媒体引用 |
| `PUT` 同上 | 预期版本保存，成功返回ACK |
| `POST /v1/workspaces/<UUID>/media` | 受限二进制媒体上传 |
| `GET /v1/workspaces/<UUID>/media/<SHA256>` | 鉴权下载与哈希校验 |

所有数据请求校验Origin、短期内存会话、工作区，写入额外检查CSRF。令牌绑定服务实例和Origin，不同工作区或同一Origin的另一服务不可复用。最多64会话、默认每会话每10秒120次、8个活动请求、32个连接；请求/头/客户端超时明确。媒体禁止HTML/SVG等可执行类型，响应带`nosniff`、attachment、CSP，接口不返回磁盘路径/SQL/令牌。

授权只能由进程内`issueSession(origin)`签发；**没有匿名HTTP“获取授权”端点**。隔离验收由测试启动器生成0600的临时init脚本，用Playwright注入自己创建的空浏览器资料；脚本不通过HTTP提供、不含在URL或日志中。测试结束撤销服务会话并移除临时授权脚本，保留合成数据库用于复验。

这不是正式客户授权流程。正式启动器如何向3100页面交付会话、会话续期、XSS/CSP整合必须随具体接入方案审查，不能把测试注入当成产品方案。

## 备份恢复

- `createBackup`使用SQLite在线backup API，不复制活跃的单个主库文件；备份期间拒绝写入和关闭。
- 备份覆盖全部索引媒体，包括尚未被文档引用的已上传媒体；不收录未提交索引的孤儿/暂存文件。清单记录协议/schema/工作区、文档和媒体数、文件哈希及大小；清单最后写入，缺清单的中断备份不能恢复。
- `restoreBackup`先校验全部路径、哈希、大小、数据库完整性/外键/schema/身份、文档和媒体引用，再创建全新恢复目标。已有目标、坏包、未知schema一律拒绝，不修改原数据。
- 恢复目标保持原workspaceId，但具有新物理数据根；这用于手动恢复，不允许同时启用同一业务工作区的两个分叉副本。
- 中途恢复I/O失败时保留部分目标以便诊断，不把它注册成可用工作区，不自动清空重试。
- 本地SHA清单用于检测损坏，不提供恶意篡改认证、离机备份、iCloud同步或加密。不要只备份`.sqlite`而遗漏媒体/WAL。

## 2. 用户明确批准的一行适配

文件：`web/src/components/layout/model-script-editor.tsx`。

```diff
- content: { height: "100dvh", maxHeight: "100dvh", margin: 0, padding: 0, borderRadius: 0, overflow: "hidden" },
+ container: { height: "100dvh", maxHeight: "100dvh", margin: 0, padding: 0, borderRadius: 0, overflow: "hidden" },
```

Ant Design 6.6.5 的 Modal 语义类型支持 `container`，不支持 `content`。样式值没有变化，不升级作者依赖，不使用类型强制转换或跳过诊断。补丁和批准指纹在 `上游适配/模型编辑器语义.{json,patch}`，只应用到运行副本。

`检查运行副本.mjs` 先检查作者工作树与锁定提交，再比较全部 506 个目标文件；只允许原版或这份精确适配。真实路径指向作者目录或逃出副本的符号链接也会拒绝。全部校验通过后才写入唯一批准文件。未知源/目标内容、重复替换位置、错误产物哈希都拒绝覆盖。切换上游提交时须重新审查适配，不能自动套用旧补丁。

自有保护/适配测试 **6/6 通过**；没有用真实作者仓库模拟破坏。浏览器中全屏编辑器开关 2 次，等待入场动画结束后尺寸为 1440×900，没有执行任何脚本。

## 5. 性能基线

使用纯文本固定数据集，保留原版节点/连线的视口裁剪，不强行挂载全部节点。三组为 20/30、120/240、360/1080（节点/连线）。每组分别测平移、选中后平移、滚轮缩放、高出度节点拖动，每种重复 3 次，共 36 个样本。

采集项：RAF 帧间隔 P50/P95/最大值、手势期间单独 P95、超过 50ms 的长任务、React root commit、Fiber PerformedWork 标记、CDP 脚本/任务/布局/样式/堆指标、IndexedDB put 次数。存储计数不读取载荷。

最终原始记录：`.运行/output/阶段4/2026-10-15T09-23-22.375Z/`，**36/36 个样本均验证了实际手势变化，没有 pageerror**。可随 Git 保留的质量、功能、性能 JSON 已归档到 [最终记录目录](基线记录/v0.20.0/README.md)。

表中数值为每种手势的 **3 次 P95 帧间隔的中位数，单位 ms**；括号为 **root commit 次数中位数**，包括结束后的保存等待，不是单组件渲染次数。

| 手势 | 20 节点 / 30 线 | 120 节点 / 240 线 | 360 节点 / 1080 线 |
| --- | ---: | ---: | ---: |
| 平移 | 15.3（52） | 53.4（52） | 121.1（52） |
| 选中后平移 | 26.6（54） | 53.3（54） | 95.0（54） |
| 缩放 | 15.2（74） | 15.1（75） | 40.0（77） |
| 高出度节点拖动 | 15.3（57） | 120.0（57） | 186.6（57） |

首次导航加载约 782/1777/1995ms，仅记录为单次开发环境读数，不是三次启动中位数；加载后挂载节点为 14/49/49、连线为 25/158/248。每个手势前使用作者“重置视图”按钮（居中、比例 1）并清除选择，实际挂载量还会随视口裁剪变化。高出度节点初始出线数为 19/80/80，不把总连线数误写成单节点连线数。

最终 36 个样本各记录到 1 次 `app_state` put，并非每帧落盘；一个中型拖动样本还记录到 7 次 `prompt_cache` put，已保留原始值。put 是请求计数，不代表 IndexedDB 事务已成功提交；持久化正确性由独立的刷新和 ZIP 回归确认。

可定位的优化候选，留到阶段 8：

1. `pages/canvas/project.tsx:232/3189`：viewport 是项目页状态，手势调用 `setViewport`，带动父页更新；原版虽已有 RAF 合并指针事件，仍未把镜头热路径与应用 UI 分离。
2. `components/canvas/canvas-connections.tsx` 及项目页连接循环：路径组件未 memo，父页每次提供新的选择/右键回调；固定端点的连接仍值得拆分订阅及缓存验证。
3. `components/canvas/canvas-side-panel.tsx`：节点列表本身没有组件 memo；大型画布虽裁剪画布 DOM，侧栏仍产生大量列表 DOM，需单独测稳定 props、列表虚拟化与搜索开销。
4. 作者已经为 `CanvasNode` 加了 memo、稳定回调、空引用常量及视口裁剪，不能说这些能力不存在，也不能根据 Fiber 标记直接断言每个节点每帧真实重渲染。后续应结合生产模式采样及 React Profiler 归因，避免重复实现作者已做的优化。

早期采样保留但不作为权威值：一轮滚轮被展开面板拦截（没有实际缩放），随后补充了每个手势的中途变化断言；另一轮使用 850ms 等待，没有覆盖串联 500+400ms 保存防抖，最终改为 1100ms 后重测。没有挑选最好的一轮数值作为结果。

测量限制：Vite/React **开发模式**，含测试 hook 遍历 Fiber 的开销和自动化输入开销；不能等同生产 FPS，不能当真实 React Profiler 渲染耗时。`PerformedWork` 是诊断信号，不是每个组件的精确耗时。RAF 间隔不等同输入到显示延迟。总采样包括 1100ms 等待作者保存防抖排空，同时单列手势期间指标。内存增减会受 GC 影响，一轮读数不能证明内存泄漏；日常其他程序的系统负载也未做实验室级控制。

没有大图/视频、百万历史记录、产品业务胶囊、真实生成、Agent、WebDAV 或付费 API 测试；这些能力尚未接入或明确不在本阶段。不设置虚构 FPS 门槛、不宣称性能提升百分比。

## 6. 可重复执行

所有命令在 `Guan二次开发` 执行：

```sh
node 开发工具/安装保护.mjs
pnpm install --frozen-lockfile --ignore-scripts
node 开发工具/准备原版.mjs
node 开发工具/检查运行副本.mjs --应用批准适配
pnpm test:protection
pnpm baseline:quality
```

质量脚本对所有检查分别留日志，即使 Lint 失败也记录单测和构建；最终退出 1 表示未全绿，不是测试工具崩溃。Bun 使用锁定官方 arm64 平台二进制，不执行安装脚本，不要求全局 Bun。

在一个终端启动隔离服务，另一个终端运行浏览器基线：

```sh
node 开发工具/启动原版.mjs
pnpm baseline:browser
# 单独复验
node 开发工具/执行浏览器基线.mjs --仅功能
node 开发工具/执行浏览器基线.mjs --仅性能
```

浏览器运行器使用唯一会话名、临时浏览器资料、锁定 CLI；第一处失败停止，保留 JSON/原始日志/截图，只关闭自己打开的测试浏览器，绝不 `close-all`。失败不会清空任何已有业务数据。

`归档基线结果.mjs <质量目录> <功能目录> <性能目录>` 只接受本项目 `.运行/output/阶段4/` 内的结果，检查完整性和手势校验，再生成按批次归档的可携带 JSON；已有不同记录拒绝覆盖。最终归档路径为 `开发文档/基线记录/v0.20.0/2026-10-15T09-23-22.375Z/`，早期记录保留但已标明被替代。

## 格式和元数据

请求格式与实际文件格式不一致9项：格式-jpeg（要求jpeg，实际png）；格式-webp（要求webp，实际png）；压缩-0（要求jpeg，实际png）；压缩-50（要求jpeg，实际png）；压缩-100（要求jpeg，实际png）；编辑尺寸-1800x2400（要求png，实际webp）；压缩-webp-50（要求webp，实际png）；透明-webp（要求webp，实际png）；透明-jpeg（要求jpeg，实际png）。因此返回200不能视为JPEG/WebP和压缩设置已经生效。

响应JSON的size字段与实际图片不一致7项：模型-gpt-image-2.6-1k（JSON 1024x1024，实际1254×1254 png）；模型-gpt-image-2.6-flare-1k（JSON 1024x1024，实际1254×1254 png）；模型-gpt-image-2.6-sunburst-1k（JSON 1024x1024，实际1254×1254 png）；跨模型自定义-gpt-image-2.6-1k（JSON 1800x2400，实际1086×1448 png）；跨模型自定义-gpt-image-2.6-flare-1k（JSON 1800x2400，实际1086×1448 png）；跨模型自定义-gpt-image-2.6-sunburst-1k（JSON 1800x2400，实际1086×1448 png）；跨型号大图-gpt-image-2.6-sunburst-1k（JSON 2480x3312，实际1086×1448 png）。必须读取下载文件宽高，不能仅凭响应元数据宣称尺寸正确。

实际返回流式-0: text/event-stream；流式-1: text/event-stream。仅application/json且无事件不能认定支持流式或部分图。
本次捕获事件：流式-0: image_generation.completed；流式-1: image_generation.completed。当前两条测试均只有image_generation.completed，没有partial_image事件；因此已验证SSE最终事件封装，未验证中间预览图生效。

## 其他参数证据

- 质量档：auto HTTP 200 / output_tokens=2058；medium HTTP 200 / output_tokens=2058；high HTTP 200 / output_tokens=2058；xhigh HTTP 200 / output_tokens=2058；max HTTP 200 / output_tokens=2058。响应回显档位或HTTP 200不能证明各档原生推理策略相同或不同；同token数也不是模型来源的证据。
- 编辑保真：编辑保真-low 1024×1024 png；编辑保真-high 1024×1024 png；编辑保真2.5-high 1024×1024 png。这里只证明接口接受/拒绝，未证明商品细节或文本保真提升。
- n=2：HTTP 200，解析到1张图。
- 输出格式与压缩：JPEG/WebP及JPEG压缩0/50/100的本轮请求均未得到相应格式，而是PNG；不能将随机PNG大小变化当作JPEG压缩设置生效。
- 个别编辑请求也可能出现反向格式偏差（请求PNG、实际WebP），以逐条文件字节检测为准，不概括为所有接口永远输出PNG。
- 遮罩测试只验证可提交并返回图像，没有进行遮罩外像素锁定对照。

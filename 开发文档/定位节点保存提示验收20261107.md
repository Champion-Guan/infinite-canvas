# 定位节点保存提示

## 原因

定位只改变选择和视区。视区沿用 2 秒防抖合并保存，但 `canvasSavePending` 将这段等待也判作内容未保存；实际素材读取又被 `createRecoverableApplicationStorage` 加进 `pending`，同样触发“保存中”。

修复前实页定位“数字0 · 尺寸标注”，动画期间约 95 ms 显示已保存，494 ms 到 2797 ms 的采样显示保存中，3199 ms 恢复已保存。这是等待与实际写入混在一起的状态，不代表持续写卡片 3 秒。

## 修改

- 顶部本地内容差异判断排除纯视区变化，仍检查节点、连线、会话及外观等内容变更。
- 存储状态分别报告 `pending` 写入数与 `reads` 读取数。素材读取不再被显示为保存；失败队列和真实在途写入仍报告原状态。
- 保留视区 2 秒合并、退出/隐藏页面提交、保存检查点、ACK 与失败重试规则。本次没有改变视区保存机制，也没有声称消除完整状态写入开销。

- 来源检查通过：640 文件、2028 引用、399 补丁。
- 体验/Hook 检查通过；有界 TypeScript 检查通过。

- 当前 `http://localhost:3000` 同一画布复测：定位动画和防抖期间显示已保存，实际写入才短暂出现保存中；本次各组采样可见约 0.5–0.8 秒，属于本次机器与数据的观察值，不是性能保证。

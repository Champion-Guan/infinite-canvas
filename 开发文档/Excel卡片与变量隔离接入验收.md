## 4. 网络与控制台的实际情况

不能写“控制台零错误”：浏览器会把合法的文档不存在探测记成 404 error。

- 首轮网络记录 `1792420603933-最终新隔离网络.log` 可解析 409 个有状态码的非静态请求：234 个 200、175 个 404。
- 其中 165 个 404 在同 URL 后续出现 PUT 200；剩下 10 次是 5 个未创建媒体/历史命名空间各读两次：`image_files`、`image_previews`、`image_generation_logs`、`video_generation_logs`、`media_files`。ID 根据 `app-` + SHA-256(namespace) 复核。它们按 allowMissing 语义为空，不是已保存画布缺块。
- 冷重开网络记录 `1792421079151-冷重开网络.log` 可解析 68 个非静态请求：48 个 200、20 个 404；全部 20 个 404 都有同 URL 后续 PUT 200。对应控制台 20 条资源 404，没有据此宣称控制台完全无错误。
- 两份记录中无外部主机请求，没有收费 API 调用；保存 ACK 和最终冷读均通过。

浏览器操作中曾发生测试脚本等待错误：默认 DOM 可见性检查把缓存产品也计入；连续删除/撤销没有等待原 180ms 历史合并；等待“已保存”文字而它会自动隐藏。已改用 Playwright 可见定位、250ms 历史稳定窗口、真实 storage status/flush 复验。保留原失败日志，没有为使测试通过而更改批准的应用代码。

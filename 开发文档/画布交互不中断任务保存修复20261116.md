# 画布交互不中断任务保存

## 原因

`ProductCommitCheckpoint.commit` 在收到 `ready=false` 的 React 提交时立即拒绝待处理保存，错误文案为“当前画布正在编辑或移动，请完成操作后再切换”。图片任务在登记身份或保存结果时也经过这一检查点，拖动、缩放、恢复或定位动画与保存重叠便会传播成任务错误。

## 修改

- 忙碌帧保留原保存票据，等待可提交的最新完整快照，不写入中间手势状态。
- 交互结束后的 React 提交自动兑现原票据并继续原保存流程。
- 同步交互引用已变化而没有后续 React 提交时，每 250ms 请求一张新渲染票据核实，避免重复使用同一个 state 值导致 React 跳过更新；持续交互不再触发原 10 秒错误。
- 尚未获得任何忙碌提交的页面确认超时、卸载代次失效、真实持久化错误及 SQLite 确认仍保留；卸载清理等待计时器。
- 不改上游生成提交、原任务 ID、结果交付与保存确认流程。

## 验证

新增虚拟时钟用例覆盖交互超过 15 秒后续存、多个结果保留、渲染票据递增、卸载清理、页面未提交超时和真实持久化失败。连同失败状态保存、批量保存竞态、画布驻留与产品即时切换共 46 项通过；有界 TypeScript 检查通过。

当前开发服务沿用 localhost:3000 和原工作区，监听器已构建本次修改。根目录映射与引用检查通过。

实页验收未完成：浏览器通道连续两次连接超时，无法检查截图中已失败的原任务是否恢复。没有点击原任务重试，没有新建收费请求，也没有宣称旧任务已修复完成。

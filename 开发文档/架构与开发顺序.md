# 两个目录，一条清楚的边界

```
AI-Workbench/
├── infinite-canvas-upstream/    原作者完整 Git 历史和原版文件
└── Guan二次开发/                我们自己的独立 Git 仓库
    ├── 扩展功能/
    ├── 上游适配/
    ├── 界面资源/
    ├── 开发工具/
    ├── 开发文档/
    ├── 上游基线.json
    └── .运行/                  忽略提交的原版工作副本、依赖和测试资料
```

上游仓库 main 追踪 basketikun/infinite-canvas 的 upstream/main，保留 MIT、作者 UI 与全部提交。Guan 仓库在 guan/develop 分支开发；不自动关联旧版远程，避免覆盖旧项目。两者的联系由“上游基线.json”锁定。原作者源码更新时，Guan 的 Git 历史不受影响。

## 当前目录与启动（2026-10-22）

已按用户要求恢复根目录五类职责，业务由`扩展功能`维护，作者差异由`上游适配`中的有序小补丁维护，`.运行/3100源`只作为装配目标。`npm run dev`启动原3100并监听根来源，当前数据与3000对照方式以[当前开发流程](当前开发流程.md)为准。功能入口、首组拆分和回退见[目录归并与功能定位](目录归并与功能定位.md)。

以下阶段2/阶段6的审批、独立会话和数据隔离描述保留为历史设计，不取代当前用户已授权的开发方式。

## 阶段2原版基线启动（历史）

在 Guan二次开发 目录运行：

```sh
node 开发工具/准备原版.mjs
node 开发工具/启动原版.mjs
```

访问 http://localhost:3100 。端口被占用即停止，不终止占用进程。Ctrl+C 只停止本次原版开发服务。依赖用作者 pnpm-lock.yaml 冻结安装；作者 package-lock.json 与 package.json 不一致，npm ci 不可复现，暂不修改原作者锁文件。

运行副本由锁定提交 git archive 生成，不在原作者文件夹安装依赖。pnpm 忽略依赖生命周期脚本；启动和构建的实际结果另行记录。不要直接编辑运行副本，后续修改必须在本开发目录内真实源文件实现。

## 数据边界

3100与旧版3000、8888、5174仍隔离；当前启用链路已改为本机SQLite/媒体目录，浏览器Origin不再保存唯一业务副本。本阶段不复制旧数据、不连接旧Keychain，不启动原版Agent或代理服务，不填真实客户凭据。日常启动只通过已批准助手读取新工作区专用主密钥；兼容上游的凭据会解密到页面内存，不能称为全面后端密钥代理。浏览器验收用独立测试会话，不读取现有Chrome配置；真实外网生成尚未验收。

## 上游更新

1. 执行 `node 开发工具/检查上游更新.mjs`：只 fetch 并显示差异。
2. 审查提交、依赖、插件协议、存储格式和 UI 变化；保存两个仓库的当前状态。
3. 在上游仓库建立临时验收分支验证作者新提交，绝不夹带 Guan 修改。通过后用 fast-forward 更新其 main，不 rebase、不改作者提交。
4. 在 Guan 功能分支更新基线提交、版本，生成新的运行副本；旧提交对应副本可保留回退。
5. 测试原版画布、设置、主题、插件，再测试所有已实现 Guan 适配。通过后才合入 guan/develop，不自动推送发布。

## 接入原则

先分析作者现有插件接口，能用插件的功能都通过协议接入。目录存在不代表功能已挂载。本阶段不移植旧功能，不为将来功能编造通用桥接层。无法由现有接口接入的功能先独立实现并提出最小接入设计，经用户批准后再决定；不能承诺任何功能都完全零核心改动，也不能偷偷在构建阶段改作者源码。

### 阶段6 本机数据存储基础

当前批准启用链路已改用本机Node.js SQLite服务，受测流程Storage/IndexedDB调用及Cookie为零；不据此推论所有未启用功能和第三方依赖都无浏览器存储行为。目标是让客户的重要数据由本机服务管理，浏览器只保留界面状态、临时数据和可重建缓存。仅修改数据库名称不能让IndexedDB跨Origin共享。

- 目标是业务数据库保存工作簿、产品、画布节点、连线、历史、任务和持久偏好；图片、视频和导入资源保存到媒体目录，数据库记录文件引用与校验信息。Node内建SQLite已接入3100，后续客户业务表义仍需阶段7定义。具体契约见 [阶段6方案](阶段6扩展边界与SQLite方案.md)。
- 数据根独立于源码、安装版本和端口，按本机用户及稳定工作区身份隔离。当前新工作区在`/Users/guanchengbin/Library/Application Support/AI-Workbench-重建版/工作区`，不接旧私人目录。
- 本工作区主密钥保存在独立Keychain项，业务凭据加密存SQLite、应用文档保存引用；兼容上游仍会解密到页面内存。全面后端请求代理不是阶段6已完成项，不能以目录隔离或密文存储代替端到端密钥安全；备份不含主密钥。
- 先定义版本化读写契约、持久化确认、并发冲突、媒体与元数据提交及异常恢复；页面显示“已保存”必须对应真实写入确认。备份覆盖数据库和媒体，并记录引用、条数及哈希；空间不足、写入中断、未知格式和恢复冲突必须安全停止。
- 本地服务检查 Host、精确授权的 Origin、会话和 CSRF，限制文件路径与外部请求。不能为了顺延端口开放任意 Origin、任意文件或系统命令。

验收先用合成数据：写入后重启完整；备份恢复可核验；不同测试端口和浏览器经授权读到同一工作区；另一个工作区不串数据，未授权网站不能读写。核心存储接入仍需具体最小 diff 单独审查。真实旧数据迁入留到阶段11，验证完成前不删除旧存储。

### 阶段10 默认3000与自动顺延

本机持久化和安全服务验收后，正式入口默认 `http://localhost:3000`。3000被无关服务占用时依次尝试3001、3002，直至找到可用端口或明确报告启动失败；不终止占用程序。

若同一工作区已经运行，先核实应用身份、数据根和进程归属，复用其真实地址，不再启动第二个实例。其他工作区不能冒充当前实例。启动器以实际端口绑定结果处理冲突，不能只靠启动前探测；监听限于本机，并维护可核验的实例记录。

健康检查通过后自动打开实际地址；桌面快捷入口查询或启动所属实例，不写死3000。普通在线更新优先保留当前实例地址；再次启动若因占用顺延，由授权的后端读取同一数据根，不触发业务数据迁移。浏览器缓存或会话可能需要重新建立，不能承诺所有浏览器状态跨端口继承。

必须测试3000空闲、连续占用、并发启动、残留实例记录、服务启动失败、多个工作区和电脑重启后的快捷入口。端口顺延不得导致客户数据丢失、重复写入或未经授权访问。当前原版3100测试入口仍固定，以上行为待阶段10实现。

## 防误改

`node 开发工具/检查上游保护.mjs` 检查原作者目录工作区和基线提交。本地 pre-commit/pre-push Hook 执行该检查；新克隆后要重新配置 Hook。Hook 可绕过，不是文件系统权限隔离。原作者仓库禁用推送 URL，仅 fetch；本阶段不推送任何仓库。

新克隆或移动整个文件夹后执行 `node 开发工具/安装保护.mjs`，恢复本地 Hook。执行 `node --test 开发工具/保护规则.test.mjs` 验证干净仓库可通过、提交不一致/源码误改/误放未跟踪文件被拒绝；测试使用临时假仓库，不修改真实原作者文件。

同步工作由 Codex 按上述流程实施，不要求用户自行判断依赖。同步前后运行保护检查；更新基线需同时记录旧/新提交及真实测试结果。不要自动跟随远程 HEAD 升级依赖，不要使用 `reset --hard`、强推或无关历史合并。

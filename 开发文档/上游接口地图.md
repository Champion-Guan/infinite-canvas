# 外挂式开发：已核实的接口与边界

本记录对应 `上游基线.json` 锁定的 v0.20.0。这里只记录真实源码能力，不新增插件功能。

以下位置均相对旁边的 `infinite-canvas-upstream`：

| 上游位置 | 实际作用 |
| --- | --- |
| `plugins/canvas/README.md` | 节点插件安装、开发、构建与安全说明 |
| `plugins/canvas/sdk/src/types.ts` | 作者插件 SDK 类型 |
| `web/src/types/canvas-plugin.ts` | 宿主侧节点、面板、工具栏及画布上下文契约 |
| `web/src/lib/canvas/plugin-loader.ts` | URL 安装、启停、更新、开发插件与本地插件加载 |
| `web/src/lib/canvas/plugin-runtime.ts` | 插件运行时及宿主 React 能力 |
| `web/src/lib/canvas/canvas-event-bus.ts` | 插件事件与按插件 ID 隔离的 localForage 存储 |
| `web/src/pages/canvas/hooks/use-plugin-host.tsx` | 画布页面提供给插件的宿主能力 |
| `web/src/router.tsx` | 页面路由；未提供任意页面路由注册协议 |

## 可以直接用作者接口承载

- 独立节点类型及其渲染内容、自定义节点面板、节点悬浮工具栏按钮。
- 读节点与连线、更新节点属性、查询上下游、执行画布指令（包括创建节点、连线、视口及生成）。
- 使用宿主提供的图片/视频/文字生成能力，而不是自行读取 API Key。
- 按插件 ID 保存私有状态、插件间事件通信。
- 在插件管理器使用 JS URL 安装；开发时可以使用作者现有 `VITE_DEV_PLUGINS` 接口。

未来我们的插件源码放 `扩展功能/`，适配作者 SDK 的代码放 `上游适配/`，产物进入忽略提交的运行目录或独立插件服务。作者示例构建脚本默认向原项目的 `web/public/plugins` 输出，**不得在原作者目录直接执行该构建脚本**；后续使用自有构建入口指定运行副本或独立产物目录。

## 不可假设已经有通用接口

现有节点协议不是整个应用的插件框架。顶部产品胶囊、全局页面路由、设置页布局、连线路由算法、画布热路径性能、全局动画替换等，并非上述节点协议自然支持的能力。以后需要这些变化时，先审查原作者新接口，再提出最小接入设计；不能通过改 DOM、覆盖所有 CSS 或暗改运行副本假装实现隔离。

如确实需要最小核心接入补丁，必须先获用户批准，补丁及说明保存在 `上游适配/`，仅作用于可重建副本，并独立做冲突检测、回归及差异记录。绝不能修改 `infinite-canvas-upstream` 的工作树。当前未实施任何补丁。

## 安全与升级约束

- 插件在页面内直接执行，不是沙箱；作者 README 明确说明其可能访问浏览器本地 API Key。插件私有存储命名空间是组织隔离，不是权限隔离。
- 当前原版仍由前端保存凭据并直连 API。使用宿主生成能力也不会自动把旧安全机制改成后端 Keychain。
- 插件用自有 ID 与命名空间，不修改内置节点定义；卸载不主动删用户数据。
- 每次上游更新都比较上述类型与加载器，并验证已实现插件；Git 能正常同步不代表接口一定兼容。
- 本阶段没有移植旧项目功能，没有连接旧 Keychain、Mihomo 或 Agent，没有做用户数据迁移。

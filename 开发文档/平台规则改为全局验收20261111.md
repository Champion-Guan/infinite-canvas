# 平台规则全局共享

用户要求：规则只属于平台。所有选择同一平台的产品、参数卡和新卡统一使用同一份规则，不再按参数卡分别保存。

## 实现

- 参数卡保留铅笔入口，区域标明“平台规则 · 全局”，弹窗明确“适用于所有选择该平台的产品”。保存、清空和恢复默认均作用于该平台；取消及未保存的恢复默认只改变草稿。
- 全局规则经本机存储桥写入 SQLite preferences，保存等待落盘确认；各参数卡及提示词订阅同一份状态。切换平台只选择对应规则，其他平台互不覆盖。
- 首次升级如有旧自定义规则，从最近更新的产品中按平台选取一次，保留旧卡字段供追溯。全局状态创建后，旧卡、导入或恢复卡片不再覆盖它。新卡不再复制规则文本。
- 策划读取当前全局规则；规则变化会提示原方案需重新策划，并拒绝旧资料请求覆盖新资料。恢复旧卡片不能暗中修改全局规则。

## 验证

- 全局规则、编辑器、实际 SQLite 存储与启动/保存检查共 43 项通过；覆盖跨卡共享、分平台、清空、重开、首次迁移、并发冲突和保存失败重试。
- 相关业务回归 191 项通过；SQLite 会话恢复 14 项通过。最后移除新卡规则副本及兼容缺省平台后，规则专项 14 项再次通过。
- 完整类型检查、相关 React Hooks 检查通过；按 react-best-practices 检查订阅生命周期、不可变快照、异步保存门禁和无障碍标签。
- 最终 `npm run dev:check-source` 通过：676 文件、2216 引用，旧前端引用为 0。
- 当前 `http://localhost:3000/` 实页验证：编辑保存临时规则，再恢复原文；另一个原参数卡显示全局规则。弹窗标明平台与全局适用范围，临时验收文字已移除，弹窗已关闭。
- 跨产品自定义同步及重启持久化由专项和实际 SQLite 重开测试验证；未在实页额外执行完整产品切换或付费生成。

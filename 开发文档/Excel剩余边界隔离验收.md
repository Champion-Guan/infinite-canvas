## 4. 取消后晚到结果

为了稳定覆盖异步竞态，仅在独立测试页面临时延迟名为 A.xlsx 的 `File.arrayBuffer()`；不修改应用模块、磁盘包、SQLite host 或授权实现。

1. 记录已保存的 `canvas_store` 字符串作为基准。
2. 用真实文件选择器上传既有合成 A.xlsx，应用显示“正在读取文件…”；确认实际挂起 1 次读取。
3. 点击读取中弹窗真实的“取消上传”按钮，等待弹窗卸载。
4. 上传既有合成 B.xlsx，应用显示 B.xlsx、独立产品B 的新预览。
5. 释放 A 的真实文件读取，等待完成及后续渲染。B 预览仍保持，A 不重新出现。
6. SQLite 的 `canvas_store` 与取消前基准字符串完全相等，`saved/pending=0/errors=[]`。
7. 恢复原生文件读取方法，正常点击 B 的“导入 1 个产品”。B 导入成功且产品分组正确。
8. 停机冷读及重开后最终冷读均确认只有 XLS 与 B.xlsx 两工作簿，没有被取消的 A.xlsx。

关键结果：`held=1, resolved=1, baselineUnchanged=true, fileReaderRestored=true, newPreviewRetained=true`。

证据：`1792412490843-取消后晚到A不得覆盖B.log`、`剩余-取消晚到仍为B.png`、`剩余边界最终冷读.json`。

这覆盖“旧文件读取晚于取消，并晚于新预览”的真实 UI 场景。同步主线程 SheetJS 解析期间无法交互的调度特点不因此改变，不宣称有后台线程解析或进程崩溃恢复能力。

# 桌面冷启动反馈

## 范围

当前本机桌面 `AI-Workbench.app` 转发到项目启动脚本，再调用 `开发工具/一键启动工作台.mjs`。原先直到编译、服务健康检查完成才打开浏览器，期间没有可见反馈。本次只修改这条开发桌面入口，不修改客户安装包，不发布版本，不修改产品数据。

## 实现

- 在读取服务状态之前启动轻量原生窗口，不依赖工作台HTTP服务或前端编译。
- 使用嵌入式 Swift/AppKit 助手应用，由 LaunchServices 正式启动并运行 NSApplication 主循环；不再通过后台 JXA/osascript 创建窗口。
- 使用已有图标、AI-Workbench名称、系统深浅色和 AppKit 原生横向不确定进度条；不显示虚构百分比，并尊重系统减少动态效果设置。
- 助手必须写出窗口显示回执后，服务启动流程才继续；服务就绪后先写关闭状态，助手自行退出并回执，父进程不再 SIGKILL 结束窗口。
- 原生进度条使用 136×12 pt 控件尺寸，替换曾经越出灰色轨道的自绘动画。
- Chrome 中已有同源工作台标签时，通过 Apple Events 激活并复用原标签；没有同源标签时才打开一次新页面。拒绝自动化授权时显示明确权限提示，不回退为重复开页。
- 冷启动先按锁文件恢复前端依赖，再准备服务运行依赖 `undici` 和 `yaml`；npm registry 失败时按配置重试。依赖完整后用指纹跳过重复安装。
- 桌面入口使用非阻塞锁，启动中的重复点击不排队；打开成功后5秒内抑制重复页面。
- 关闭提示窗口不停止后台服务。失败提供可读提示和查看启动日志入口；反馈组件异常不阻断启动服务，原生窗口异常写入有界启动日志。
- 不引入常驻服务、浏览器等待端口、额外数据副本或自动备份。

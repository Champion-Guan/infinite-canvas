# 存储、刷新与产品切换提速验收

日期：2026-10-24。实际开发服务为 `http://localhost:3001`：旧项目占用3000后自动顺延。本轮沿用原工作区及现有 Chrome，没有修改旧3000项目、另起验收工作台或触发生图。

## 已定位的原因

慢速不是单条 SQLite SQL 写入本身造成的。主要等待发生在业务快照、媒体编码和本机请求调度之间：

1. 首屏恢复逐块经过鉴权 HTTP 读取，当前数据需要约127次请求；请求窗口耗尽后出现整段等待。
2. 原启动流程先扫描容量，将可延后操作放到了首屏之前。
3. 相同图片的126处引用重复读取或创建临时地址；恢复后的新 Blob URL、克隆 Blob 又被视为新素材处理。
4. 后台历史、图片读取与保存共用排空队列；保存等待无关后台读取，保存新分片所需的读取也可能被普通读取占满预算。
5. 刷新或切换时，等值对象、恢复的媒体临时地址及仅变化的项目修改时间，仍制造新的整库提交。
6. 产品切换中的工作簿记忆和导航偏好分成两次 flush，串行增加等待。
7. 等值引用复用后，上游保存提示仍按引用身份判断，导致数据库已提交但页面长期显示“保存中”。已接入同一套精确变化判断修复。

| 操作范围 | 本轮处理 |

## 真实页面和数据库验收

现有数据共145个产品；当前工作簿显示6个产品胶囊。使用5节点的“便携旅行缝纫包”和104节点的“玩偶/软体玩具缝纫套件”反复刷新、切换。

| 场景 | 实测结果及口径 |
| --- | --- |
| 页面刷新 | 无重测试并发竞争时，记录到2.845、3.178、3.631、4.577秒；到目标产品/输入框可见，随后另核验图片与保存完成 |
| 刷新后立即切换5→104节点 | 2.408秒到目标胶囊选中 |
| 连续产品切换 | 0.994、1.209、1.263秒；最终补丁复验0.802与1.168秒到目标胶囊选中 |
| 真实字段增加临时标记 | 动作发起09:24:14.871Z；SQLite根revision1267提交09:24:16.383Z，1,512ms |
| 刷新恢复真实编辑 | 输入框恢复临时标记，确认不是只显示前端内存状态 |
| 恢复原字段 | 动作发起09:25:13.853Z；SQLite根revision1268提交09:25:18.214Z，4,361ms；库中标记不存在，原字段保留 |
| 保存状态 | 刷新、切换和编辑后最终均显示“已保存”，无永久保存中或右下角重试框 |
| 图片完整性 | 大画布51/51、另一次切换56/56已挂载图片完成加载；最终页面控制台无 warning/error |
| 生成历史 | 现有页面约1.273秒显示历史；下载、总览入口保留，没有触发生成或重试任务 |
| 本地存储面板 | 成功显示当前业务132.0MB、实际占用约227.5MB、历史保留81.7MB；没有清理任何数据 |

时间包含浏览器自动化传递、前端处理与数据恢复，不是纯 SQL 耗时；多次页面测试期间曾遇重测试/构建竞争，刷新约12秒、切换8–18秒。本表将无竞争记录单独列明，不保证所有机器、所有数据规模都达到这些数值。启动仍约3–5秒，尚未达到旧浏览器库的瞬时恢复体验。

此前保存提速验收记录在 `开发文档/保存提速验收.md`：同字段真实落盘曾为40,544ms，第一轮优化约2–3秒。本轮真实编辑为1.5–4.4秒；不能将这些样本等同所有编辑的保证值。

临时验收标记已从真实参数恢复清除，没有改动其他用户字段；最终返回用户原先的“便携旅行缝纫包”。

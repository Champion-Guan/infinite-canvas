# 阶段 3：分批开发与验收计划

本文件规定后续实施顺序，本阶段没有执行业务迁移。建议清单见 [功能取舍清单](阶段3功能取舍清单.md)，接口边界见 [外挂接入方案](阶段3外挂接入方案.md)。

## 1. 开发顺序与门禁

总阶段沿用桌面原开发顺序：4 建立测试与性能基线 → 5 小批关闭或删除功能 → 6 建立扩展边界与本机持久化 → 7 分批迁入客户功能 → 8 性能专项优化 → 9 视觉与动画 → 10 启动、端口与在线更新 → 11 旧数据兼容 → 12 正式切换发布。阶段6的存储基础先于客户功能持久写入；凭据网关必须在阶段7真实生成前验证，不能拖到最后。

原稿把业务批次误编为 `4-*`，现纠正为 `7-*`。阶段 4 只建立质量、功能及性能的可重复基线，不迁业务、不做性能优化。阶段 3 只是接入规划，不能算阶段 6 已实现。

| --- | --- | --- | --- |
| 阶段4 原版质量门禁 | 先核对作者修复；若仍有 Modal 类型不匹配，单独审查最小运行副本适配；建立原版功能/性能基线 | 不改作者工作树、不跳过类型错误、不升级依赖赌兼容 | 冻结安装可复现；typecheck、build、原版可运行测试与模态窗口回归均有真实结果；缺失测试运行器明确解决 |

| 7-3 产品工作区 | 经批准的最小接入口；产品胶囊、工作表切换、命名、空白页、回收站/恢复；任务用模拟器 | 不复制 iframe 缓存、DOM 注入，不宣称真实跨产品生成完成 | 切换/刷新/删除/恢复数据归属正确，异步保存冲突可恢复；模拟任务结果仍回原产品；每份接入 diff 已批准 |
| 7-4 凭据与网络 | 新测试命名空间的 Keychain 网关、显式渠道/代理能力、前端 opaque ref、输入/日志安全 | 不自动迁旧密钥，不用任意命令/URL 代理，不开放任意脚本 | 模拟 API 覆盖认证/超时/重试/脱敏/CSRF/地址策略；所有启用入口安全一致；bundle 和浏览器存储无真实密钥 |

先验收6-1、6-2，再完成7-1、7-2的可演示小闭环，然后确定7-3的具体核心接入口。阶段3的批准可以确认功能范围，但不能代替未知核心diff的逐批审查。

## 2. 每批统一操作流程

1. 检查两个仓库状态，保护用户改动；运行 `node 开发工具/检查上游保护.mjs`。
2. 从 `guan/develop` 建独立功能分支；阶段 3 规划留在 `guan/stage3-plan`，不自动合并。
3. 列出本批功能、真实宿主能力、拟新增/修改自有文件、若需要则列出具体最小补丁。
4. 先写最小固定样例和失败测试，再实现自有模块；不加无关功能。
5. 在可重建运行副本测试。依赖冻结安装、类型检查、构建、适用单元测试与隔离浏览器端到端分别记录。
6. 比较相对上游差异；作者工作树必须干净，自有 Git diff 无无关文件，依赖/构建大小记录但不作为唯一质量依据。
7. 给用户可复现演示及剩余风险；本地提交只暂存明确自有文件。合并、启用真实数据、重启旧服务、推送/发布都遵守各自审批边界。

阶段 3 只有 Markdown 文档变更，因此其验收是保护检查、文档证据与链接一致性，不是假装跑完所有业务测试。下列都是未来测试要求。

## 5. 性能测量方法

先采集原版，随后每个功能批次用同一台 Mac、同浏览器版本、同窗口、缩放、缓存状态与数据集重测。数据集按节点/连线/图片数量和媒体大小定义，不先把数量当产品硬上限。

测量内容：

- React Profiler：平移每帧是否使项目页、全部节点、侧栏与产品导航提交；把实际订阅与提交堆栈定位到源码。
- 浏览器 Performance：输入到画面延迟、长任务、帧耗时分布、布局/绘制、GC；不是只看平均 FPS。
- 存储：拖动中序列化次数与 IndexedDB 写入；保存完成后重载正确性。
- 产品切换：点击到可交互、资源读取/解析时间、缓存驻留内存，连续切换后的内存趋势。
- 多连线拖动：重算路径数、所有节点重渲染数、未动节点提交数；确认优化不会漏连线/端点。

验收目标是减少与手势无关的更新，并不牺牲保存正确性。正式数值目标在实测基线后与用户确定；阶段 3 没有 FPS、内存或启动速度测量，不宣称已提升百分比。

## 6. 动画实施规则

先实现自有顶栏、参数节点、导入、保存/任务状态，再按实际需求局部接入作者 UI。优先复用作者已有 `motion` 依赖，不安装重复全局动画系统。

- 弹窗、遮罩、Portal 定位与内容入场只能有一个生命周期负责人；避免全局 transform 改变 fixed/Portal 坐标或 pointer-events。
- 平移、缩放、指针拖动保持跟手，不加弹簧缓动追鼠标；吸附反馈发生在结束/确认后。
- 主题与 reduced-motion 跟随系统；关闭动画时状态、焦点和保存反馈仍完整。
- FLIP/共享元素只用于稳定 key 与明确节点，取消/切换/卸载清理动画，不每次 render 重播。
- 原版先测正常，再测适配，出现卡顿/闪烁/不可关闭即阻止合并，不能只看截图。

## 7. 阶段 3 与阶段 4 的交接

阶段 3 完成条件是：功能清单、真实接口与缺口、拟文件地图、批次和验收可审查；作者与旧项目未被修改，保护检查通过。阶段 4 只建立测试与性能基线；涉及原版阻塞的最小适配仍需提供具体差异单独批准。业务迁入必须等阶段 5、6 完成之后。

阶段4已有基线记录，剩余门禁见对应验收文档。当前阶段5首批功能策略与候选补丁已准备，具体接入待批准，3100尚未启用。阶段6本机持久化、阶段10默认3000顺延均为新增规划；真实API、旧数据迁回、运行接管和发布本轮不执行。

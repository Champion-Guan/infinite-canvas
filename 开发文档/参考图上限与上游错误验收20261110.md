# 参考图上限与上游错误

## 问题与修复

- 中转返回的 HTTP 400 响应已由渠道网关脱敏并保存到任务结果媒体。旧任务衔接只检查终态，并统一抛出“原生成任务未成功”，没有读取错误正文，因此工作台提示与中转日志不一致。
- 失败任务现在通过原任务 ID 读取已保存响应，核对产品、卡片、内容大小及 SHA256 后提取明确错误字段，显示 HTTP 状态与中转原因。支持 error.message、字符串 error、message、msg、detail 和纯文本错误。HTML、无明确错误字段的 JSON、异常编码及超大错误正文使用状态提示，不显示整份内部响应。
- 沿用渠道网关已有凭据脱敏；错误展示额外隐藏明显的 Bearer、sk- 凭据形式。没有新增上游调用、重发或故障切换。
- 单次生图请求的参考图上限统一为 14 张。新任务在图片读取、编码及结果卡创建前检查；批量入口在任何任务执行前检查整批；协议层覆盖重试和图片工具，原图片编辑服务也复用同一上限。
- 本次使用的专属图、共用图及编辑时带上的原图合计计数，同一节点去重。超过上限明确显示“参考图最多支持 14 张，当前有 N 张。请减少参考图后再生成。”
- 不截断图片清单，不删除素材，不限制产品可保存的总素材数量。两个变体可各自使用 14 张不同图片。
- 已有成功结果的恢复继续按原任务读取，不因新上限阻止已完成响应的交付；真正创建新请求时才执行协议预检。

# 空格拖动与画布按钮焦点

## 原因与改动

- 鼠标操作“AI写提示词”后，浏览器焦点仍在原按钮。旧画布忽略原生按钮上的空格，因此按下、松开空格会由浏览器再次激活按钮。
- 参数卡内容另有 `data-canvas-no-zoom` 标记。首次修订只放行鼠标操作过的按钮，仍被这层标记拦截；实页发现后同步修正该边界并补充同结构测试。
- 画布捕获指针阶段记录最近的命令按钮，只为该按钮保留的鼠标焦点接管空格；按下、长按重复和松开都阻止原生按钮激活。空格状态另用 ref 同步，拖动不必等待 React 下一次渲染。
- Tab、Enter 或其他非空格键开始键盘操作时清掉鼠标意图。通过键盘聚焦的按钮仍能用空格激活，输入框、输入法、开关、页签和可见模态窗口保留原行为。
- 失焦、产品隐藏和卸载清除临时状态及监听；保留既有 Ctrl/Space 临时切换选择与移动工具的规则。

## 验证

- 38 项相关测试全部通过，包含真实 InfiniteCanvas 组件监听、与参数卡一致的禁止缩放内容层、长按和松开、即时拖动、Tab/Enter、输入与弹窗边界、失焦及隐藏清理，以及既有平移和侧栏交互。
- 完整 TypeScript 检查通过。来源检查 659 文件一致、2132 引用，468 个顺序接入补丁。
- 在已有 localhost:3000 页面通过从 AI 按钮按下后拖出并松开的方式保留焦点，不点击执行策划。实际按住空格时 cursor 为 grab，松开恢复空值，按钮始终为“AI写提示词”，没有变为“取消策划”。
- 原生键盘按住空格期间拖动画布，变换从 `translate(444.594px, 57.3084px) scale(0.6877)` 变为 `translate(524.594px, 107.308px) scale(0.6877)`，实际移动约 80 × 50 CSS px。
- 搜索框输入“键盘”后按空格，值为“键盘 ”。Tab 从 AI 按钮进入“上架平台”后，空格正常展开原生菜单，Escape 关闭；未改变平台。
- 当前画布仍为 52 个节点并已保存。截图：`.运行/验收截图/空格移动不再触发策划.png`。

# 策划结果自动保存确认

## 改动

画布的“已保存”与生成任务的结果确认是两道不同边界。原卡片已有策划和收据，但任务确认中断时会显示“继续保存”，只能手动重新进入恢复流程。

- 参数卡当前挂载且画布激活、已有待保存结果、没有正在运行的本卡操作时，自动调用原策划入口的recoverOnly路径，保存画布并确认原任务。包括新版pendingCommit和旧版已有收据但缺少pendingCommit的情况。
- 自动入口不进入查询原任务、继续修正或新策划。副本沿用原独立身份修正规则，不拿原卡任务自动保存到新产品。
- 自动操作显示“自动保存中”。短暂保存或连接错误最多尝试3次，间隔0、2、6秒；普通节点更新不重新计算尝试预算，清保存标记后落盘失败、标记恢复时也不重置预算。
- 正在策划时不并行自动保存，等待原操作结束；隐藏画布暂停尚未开始的计时，重新激活后继续。节点或任务变化清理旧计时器；卸载取消原按钮持有的请求。
- 未找到任务、归属/收据不匹配、协议错误和未知错误不会循环重试。持续失败保留原卡、原任务与“重试保存”入口，不把尚未确认的结果标成成功。
- 不增加模型调用、任务ID或独立保存副本；正常画布事务、实际SQLite回执和原任务确认继续生效。

## 验证

- 新增策划自动保存专项：自动触发、旧身份恢复、不重复调度、2/6秒退避、隐藏/策划中暂停、同任务不并发、切换身份清理、未知错误停止。
- 按钮测试实际捕获自动保存回调，确认save身份使用recoverOnly:true、repairOnly:false；查询和修正没有自动保存身份。
- 原协议恢复测试确认：已有结果的补保存不增加模型请求、不重做applyOps，保存或确认失败保留pendingCommit；成功后清标记且保存完成状态。
- 5个文件46/46通过，覆盖流式预览、自由输入、复制卡片、旧版收据恢复等；完整TypeScript检查和两个修改模块Hook检查通过，源码装配737文件、2466处引用一致。
- 开发服务自动构建已更新，localhost:3000 ready、HTTP 200。没有执行收费生成或手工改动用户任务状态。

# 策划图片请求上限实测

2026-11-13，对当前本机文字渠道 Hi-Code（`https://api-cn.hi-code.cc`）、
`gpt-6.1-sol`、`/v1/responses` 进行真实请求验证。使用合成红底测试图，
不发送客户产品图片，不创建工作台业务任务。凭据只从已有保管端口读入进程内存。

## 服务商结果

| 请求 | 结果 |
| --- | --- |
| 小图 Base64 data URL | HTTP 200，回答 Red |
| 公网图片 URL | HTTP 200，回答 White |
| Files API multipart 上传 `/v1/files`，purpose=vision | HTTP 404 |
| 24MiB PNG，正文 33,554,712 字节 | HTTP 200，回答 Red，约39秒 |
| 48MiB PNG，正文 67,109,144 字节 | HTTP 200，回答 Red，约88秒 |
| 74MiB PNG，正文 103,459,780 字节 | HTTP 200，回答 Red，约106秒 |
| 80MiB PNG，正文 111,848,388 字节 | HTTP 413，openresty Request Entity Too Large |

大图测试使用合法 PNG 的可忽略 tEXt 数据块增加文件字节，像素仍为256×256，
用于验证上传及解码路径的字节限制，不代表高像素图片、图片数量或模型上下文上限。
每次成功请求输出5个token。公网URL测试使用公开示例图片。

另以 `Expect: 100-continue` 只发请求头、不发正文定位入口边界：

| Content-Length | 入口响应 |
| --- | --- |
| 100,000,000 | 100 Continue |
| 104,857,600 | 100 Continue |
| 104,857,601 | 413 |
| 110,000,000 | 413 |
| 134,217,728 | 413 |

结论：当前渠道入口的请求正文上限为100MiB。完整识别链路已验证到
103,459,780字节，边界的100 Continue仅证明入口准许上传，不能代替完整生成成功。
Files上传404，未获得file_id，因此未验证file_id识别，也没有遗留上传文件。
这些结论只适用于本次渠道和接口，不能推及所有兼容服务商。

官方图像指南当前列出URL、Base64和Files API文件ID三种输入方式，
并列出512MB请求总量；这不能替代兼容渠道的实际限制。
来源：https://developers.openai.com/api/docs/guides/images-vision

## 工作台调整

- 生成网关请求正文限制由32MiB调整为100MiB；HTTP外层Base64封装容量随之计算。
  响应结果容量保持32MiB。
- 策划图片data URL合计预算90MiB，余量留给提示词、协议字段和商品资料。
  按本次图片数量分配预算，预算内保留原图，超出时仅缩小分析副本。
- 文本请求创建任务身份前检查总字节，超限不新建或提交任务。
- 旧版已保存身份但服务端没有任务的情况，仅核实缺失后收口，不把未知网络状态当未提交。
- 策划胶囊状态核对产品和参数卡归属，复制卡不继承外来运行状态，摘要缓存包含产品身份。

## 验证范围

定向测试覆盖100MiB规范Base64、超限拒绝、12张各4MiB图保留原文、
高分辨率分析副本的真实解码与比例、准备失败前无任务身份、
旧任务缺失与网络未知的区分，以及跨画布胶囊状态。
客户截图中的12张原图和客户渠道未取得，未在客户原数据上复现。
代码测试及服务商真实请求不等于客户画布的完整交互验收。

# 产品即时切换验收

日期：2026-11-06，Asia/Shanghai。

## 问题与标准

顶部胶囊原先先等待当前画布检查点和全局 SQLite 排空，再等待目标产品导航偏好的 SQLite 确认，最后才更新路由。访问过的画布虽然保持挂载，仍被这条保存链阻塞。界面展示过渡还使用整页 View Transition。

以用户体验至上为基础：普通产品切换立即响应，后台保存不锁定后续点击；数据保护、真实保存状态和失败恢复继续成立。采用用户指定的 Apple Design 技能中即时响应、可打断和克制的原则，保留已有胶囊按压与悬浮反馈。

## 修改范围

- `扩展功能/产品/产品操作.ts`：同工作簿普通产品切换使用同步路由提交，不启用整页截图过渡；后台提交旧产品自己的 React 检查点和 SQLite 回执。
- 导航操作锁在后台保存开始前释放，连续点击可以继续切换。保存失败不撤回已显示的目标产品。
- 检查点错误明确交由胶囊界面显示，SQLite 错误继续由原保存状态条和恢复队列处理；没有静默吞掉检查点异常。
- 已保存的检查点基线不重复请求快照。节点、连线和视区的现有等值保存判断保持。
- 未完成初始化、工作簿删除待确认、跨工作簿点击仍在导航前拒绝。恢复门禁中的目标产品、新建、导入等仍采用确认后入场路径。
- 新增 `开发工具/产品即时切换.test.mjs`，加入现行全面体验回归；同步根源码映射。

## 验证边界

浏览器自动化调用包含工具通信、定位和操作等待，未把调用耗时当成实际点击到首帧的延迟，也未宣称零毫秒、稳定帧率或所有规模画布均无卡顿。保存故障路径使用可控测试验证，本次未对真实用户数据库制造断网、断电或强杀故障。

## 二、实现与数据流

```text
已授权页面闭包 → 当前Origin/页面能力/数据租约
  → 渠道绑定（不透明provider引用，不返回API Key）
  → 任务ID + 原产品ID + 原结果节点ID + 受限请求
  → SQLite任务状态确认 → 后端解析密钥并请求渠道
  → 已消毒响应存媒体目录，任务账本引用其SHA-256
  → 页面适配器应用到原产品并保存
  → 后端读取真实SQLite根/分片核验 → applied=true
```

网关只允许OpenAI兼容/Gemini的GET/POST和明确资源路径。不会继承浏览器认证头、Cookie、重定向或环境代理。生产端点要求公开HTTPS；连接时通过自定义DNS lookup只返回经核验的公网IPv4，TLS仍验证原主机。HTTP loopback只在独立测试装配的精确origin白名单中允许，正式装配不提供此例外。

页面不能选择任意URL后附带旧密钥引用。新绑定接受首次填写的密钥；既有`secret:`引用的转换只提供可信后端方法，HTTP不暴露。绑定ID由协议、端点、类型与HMAC凭据引用的内容摘要构成；已有绑定不覆盖。

请求正文不写任务日志，账本只保留摘要、归属和状态。API响应限制32MiB、10分钟；响应全文的已知凭据表示先消毒再落盘和交付。二进制中发现已知认证材料则拒绝。该消毒不是未知编码、任意提示词或插件脚本的完整DLP保证。

### 状态的准确含义

| 状态 | 含义 |
| --- | --- |
| `accepted` | 请求摘要及归属已落盘，尚未开始派发。 |
| `running` | 派发前状态已落盘；进程丢失时不能推断远端未执行。 |
| `succeeded` | 本次HTTP请求得到2xx响应且原始响应已持久保存；不代表图片已解析、视频已生成或画布已保存。 |
| `failed` | 已持久保存明确的非2xx响应。 |
| `uncertain` | 断线、超时、取消或结果保存未确认，禁止自动重新收费请求。 |
| `cancelled` | 冷启动核对到上次进程只停在accepted，未派发；不是远端取消证明。 |
| `applied=true` | 成功响应已由原产品/节点的真实保存检查确认。客户端一句`saved:true`不够。 |

同一ID及相同请求复用已有任务，包括并发点击和HTTP丢ACK；不同请求不能复用ID。结果写盘失败时可仅重试本机保存，不重发API。服务冷重开保留成功结果及已保存标记；运行中的旧任务转待核实，不自动执行。这里不承诺第三方API的exactly-once执行。

画布核验器读取当前`app_state`根及完整哈希校验分片，查找原产品、节点、成功状态与`gatewayGenerationReceipts`中的任务ID/响应摘要，前后根版本须一致。不解码配置、解密凭据或加载全部媒体。**原画布尚未写入这些回执，不能把核验器的合成数据通过当成现有画布已完成接入。**

1. 本批是请求/结果账本和端口；原生图、编辑、文字、视频、音频的请求构造、流式显示、错误处理、历史记录和卡片落位仍需原样适配，不会自动获得支持。
2. 现有凭据兼容端口仍可读回页面；后继要先在后端核对旧配置及端点绑定，再切换配置编码/表单与请求传输，最后关闭页面回读。不能只删read方法导致配置或渠道失效。
3. 当前网关缓冲完整响应，不保留流式文字的逐字进度。正式切换文字生成前必须单独保持流式行为或明确限制，不能默默退化。
4. 默认最多256条任务，最大512条；不自动删除任务、媒体或旧密文。达到上限明确拒绝，未来需归档/分页验收，不冒充无限容量。
5. 正式端点暂不支持HTTP本地模型、IPv6-only、自定义脚本、任意插件、上游压缩响应与自动网络代理。旧请求转发功能不因此被关闭或被宣称已迁入新网关。
6. 取消只能中止本机等待；第三方服务可能继续执行。断线后的远端任务不能仅凭本机状态证明已结束。
7. 备份仍不包含主密钥；跨机器凭据恢复不能仅凭SQLite备份保证。本批没有扩展阶段6已有的凭据迁移承诺。

# SQLite凭据接入：审查与隔离预审

日期：2026-10-18。当前分支：`guan/stage6-local-storage`。

## 本批的交付边界

继续采用SQLite保存业务数据、本机媒体目录保存大文件、JSON/ZIP用于配置和交换。凭据不是普通配置：SQLite内只能保留加密内容和不透明引用，解密主密钥属于本工作区的独立macOS Keychain标识。

本批实现凭据模块和接入候选，不是3100正式替换完成。既有分片四文件批准、原作者仓库、日常运行副本和全部历史审批快照保持。没有接管/重启3100、迁入旧数据、输入真实API Key、访问真实Keychain、Git提交、推送或发布。

## 1. 已实现的自有模块

| 来源 | 实际作用 |
| --- | --- |
| `扩展功能/本机凭据/凭据协议.mjs` | 浏览器/本机共享协议和上限：凭据1至2048字节，引用为不透明64位十六进制ID。 |
| `扩展功能/本机凭据/SQLite凭据保管.mjs` | AES-256-GCM加密；HKDF分离加密和引用密钥；带密钥HMAC引用去重；不可变密文先确认后交付引用。 |
| `扩展功能/本机凭据/钥匙串主密钥.mjs` | 先检查助手文件权限、类型、指纹，再通过无shell子进程的stdin/stdout读写内部材料；有限超时/输出，不把密钥放argv、环境变量或日志。 |
| `扩展功能/本机凭据/系统钥匙串.swift` | Web本机后端的受限命令行助手，不是桌面应用。固定service和工作区UUID account，仅支持read/create，不枚举、覆盖、删除旧Keychain条目。 |
| `扩展功能/本机凭据/凭据客户端.mjs` | 已授权页面的store/read端口；严格检查响应，不缓存到浏览器，不回退明文。 |

主密钥助手使用`LAContext.interactionNotAllowed`，系统锁定或拒绝访问就停止，不弹出新的工作台授权码。helper只允许当前用户拥有、不可由其他用户修改、非链接且与可信构建哈希相符的文件。此机制不声称抵抗已控制同一macOS用户账号的攻击者。

SQLite主库schema和既有2MiB文档限制不变。密文保存为现有`extension`文档，已有备份自动包含它们。业务根和分片只保存`secret:<id>`，不保存API Key明文。

## 3. 本轮测试与证据

证据根：`.运行/output/SQLite凭据接入-ECcIoE/`。全部凭据为虚构文本，主密钥为临时内存随机字节。临时数据库、编译产物和失败日志保留，不删除材料。

第一轮完整专项46项中44项通过、2项失败，记录在`凭据完整预审初测.log`：

1. 原生助手启用`-warnings-as-errors`后，发现旧的Keychain认证选项已弃用及一个未使用返回值。已改为系统建议的`LAContext.interactionNotAllowed`，不是降低编译检查。
2. HTTP启动器测试以Node fetch发送顶层导航头，实际被fetch强制替换成`Sec-Fetch-Mode:cors`，被既有导航保护正确拒绝403。测试改用显式HTTP请求；这是HTTP夹具，不冒充浏览器或原画布通过。

随后46项复测全部通过（`凭据完整预审复测.log`）。进一步补充管道/子进程失败保护，最终`凭据最终回归.log`为**49/49通过**：20项保管、16项HTTP链路、13项系统端口/编译前置测试，0失败。

主要覆盖：

- 真实SQLite/WAL只含密文；同值重复保存和丢ACK重试不重复revision，不同工作区不共用引用。
- API配置经真实凭据端口、分片编码落盘，冷客户端重新读取保持字段，图片与配置一起备份冷恢复。
- 密文、IV、标签、工作区、协议、引用、revision篡改拒绝；主密钥丢失/错误/系统拒绝不自动生成替代。
- 非空无标记工作区拒绝首次初始化；只有明确初始化的空工作区才能建新凭据保管。
- 原配置保存失败保留旧根，原FIFO队列重试全部确认后才显示保存成功。
- HTTP Host/Origin、跨站、协议、能力、方法、路径、未知字段和大小限制；页面关闭或数据租约过期后拒绝读写；执行中页面到期不返回明文。
- 候选启动器装配已批准写入协调服务，首备份包含凭据标记，HTTP闭环成功，停止重开成功，错主密钥失败后不遗留本次锁。
- 助手响应/子进程错误消毒，密钥不放argv/env；Swift真实编译，只运行非法输入前置拒绝，未执行Keychain API。

既有存储完整回归**195/195通过**（包含此前独立计数的3项媒体语义比较，不重复加总），通用保护**12/12通过**，分别记录在`既有存储完整回归.log`、`通用保护测试.log`。120份自有JS检查0错误/警告，记录在`最终代码检查.log`；候选9份JS另全部语法检查通过，Swift助手以警告视为错误编译通过。不把隔离模块或HTTP夹具结果当成新增原画布回归；本批还没有获批接入原React画布。

## 4. 不能隐去的限制

1. **系统Keychain实际读写尚未验收**。本轮不允许访问真实Keychain，模拟端口不能证明系统权限、锁屏或跨版本helper身份兼容。原生助手只编译并验证非法输入在访问Keychain前停止。后续若做系统验证，须明确授权，仅使用全新独立测试工作区标识，不读取已有用户条目。
2. 为保持当前上游配置/直连API兼容，`read(ref)`仍将密钥交给页面内存。这是安全落盘，不是密钥完全不进浏览器；后端API代理、任意正文/脚本DLP属于后续专门边界。
3. 备份包含密文，不包含Keychain主密钥。相同机器/工作区能用原主密钥恢复；复制ZIP到另一台机器不能凭空恢复凭据，需要后续安全迁移或重新填写，不能静默替换。
4. 密文和引用无GC。删除/改密钥不会立刻物理清理旧密文、备份或旧Keychain材料。
5. 页面能力和授权频率限制保持；大量渠道频繁编辑可能触发限流，失败必须保留队列，不是无限吞吐保证。
6. 页内待保存队列仍不是刷新、强关或断电恢复承诺。未知schema/异常锁继续拒绝，不强制清锁、覆盖或创建空库。

# 产品恢复挂载竞态审查

日期：2026-10-19（北京时间）。范围：产品悬浮删除十文件隔离验收发现的恢复保存/导航竞态，以及后继候选的失败重试边界。

结论：**原十文件的恢复导航仍有阻塞，不能上线。三文件复审候选通过逻辑与类型预审，可以作为下一批隔离接入对象；尚未获批接入，也未通过真实浏览器验收。**

## 1. 审查发现，按重要性排列

### P1：恢复状态发布后提前挂载，恢复操作自己的自动保存会阻止导航

位置均为只读核验的隔离包 `.运行/产品悬浮删除-OlIVTI/组合包/画布副本/`：

- `web/src/guan/产品操作.ts:143`：恢复操作依次执行当前保存、恢复状态发布、全局保存和导航。
- `web/src/guan/产品工作区.tsx:35`、`:42`、`:49`：保留访问过的ID；被删除产品重新进入活动列表后，即使不是当前产品，也会立即重新挂载。
- `web/src/pages/canvas/project.tsx:465`、`:554`、`:583`：挂载引起异步媒体恢复、画布自动保存和500ms视区保存。
- `web/src/guan/上游浏览器存储桥.ts:88`：保存调用开始时排出已调度写入；等待期间如果出现新写入，末尾检查拒绝继续。

触发：访问A → 删除A并切B → 在B的回收站恢复A。A提前挂载产生新写入，恢复函数收到“本机保存尚未确认”，没有执行后续导航。上一轮真实浏览器已复现，本轮以真实操作/工作区函数与显式调度替身重现因果链。

影响：恢复数据可能随后已落盘，但界面仍报告恢复失败、停留原产品。不能解释为已完成恢复，也没有证据表明该案例丢失了画布。

建议：恢复ID在状态发布前加入产品层挂载门禁；业务根和导航偏好均收到保存确认，且导航发起后，才允许恢复画布挂载。不卸载其他产品，不删除或放宽SQLite的最终检查。

### P2：首版挂载门禁候选的重试会要求一个尚不存在的页面检查点

首版是本轮生成但**未接入**的 `上游适配/待审查/产品恢复挂载竞态三文件.patch`，不是已批准十文件的新线上回归。

相关位置：`web/src/guan/产品操作.ts:62` 的 `commitCurrent()`，以及 `web/src/guan/产品规则.ts:79` 的 `ProductSaveRegistry.flush()`。

触发：网址本来仍指向已归档A → 恢复根或导航偏好保存失败 → A已回到内存列表但仍被门禁阻止挂载 → 点击“重试保存后继续”。首版按网址认为A需要提交页面保存；实际没有注册的画布实例，于是抛“产品画布尚未加载完成”，重试无法前进。

本轮先加入回归，修订前两个失败重试用例都失败，实际错误均为“产品画布尚未加载完成”；同时保留专门复现首版缺陷的测试。

复审修订：仅当当前ID在恢复挂载门禁中时，不要求尚未挂载、也从未开放编辑的页面提交检查点。其下的 `flushSQLiteStorage()`仍无条件执行；任何全局保存拒绝继续阻止导航。其他当前画布的检查点照常执行，失败仍阻断操作。

## 2. 三文件复审范围

| 运行候选文件 | 具体变化 |
| --- | --- |
| `web/src/guan/产品恢复挂载门禁.ts` | 新增页内恢复ID集合、稳定不可变快照和订阅；不持久化、不读写业务数据 |
| `web/src/guan/产品操作.ts` | 恢复前封住挂载；确认保存并发起导航后释放；失败留门禁；确认再次归档后清除对应门禁；修正未挂载检查点的重试边界 |
| `web/src/guan/产品工作区.tsx` | 用React外部存储订阅读取门禁，仅过滤恢复中的ID；保留其余实例的key和挂载状态 |

唯一新增显示内容：当前网址恰指向门禁中的恢复产品时，显示“产品恢复尚未确认，请勿刷新或关闭；若保存失败，请在回收站重试。”，不显示空白画布。该状态提示不改变现有胶囊、回收站和确认框的布局或样式。

失败后通过回收站的“重试保存后继续”重试。若当前在其他产品，也可经原保存检查后显式切入已恢复产品；不承诺点击已经选中的同一胶囊能解除门禁，现有同ID选择仍直接返回。

不采用的方案：

- 仅清理visited：不能覆盖原网址本来就指向恢复ID的情况，也不应顺带卸载其他运行画布。
- 去掉SQLite保存末尾检查或清失败队列：会把未确认数据伪装成成功，拒绝采用。
- 固定等待500ms或无限循环flush：不能可靠覆盖媒体异步恢复和后台任务，不作为保存协议。

没有修改SQLite桥、保存检查点、授权/限流/媒体白名单、生成任务业务、原作者仓库、历史批准对象或历史保护器。

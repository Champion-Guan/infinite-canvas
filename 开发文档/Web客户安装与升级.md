# Web客户安装与升级

仓库固定为`Champion-Guan/infinite-canvas`。当前可下载[Web 2.0.0-beta.3 预览版](https://github.com/Champion-Guan/infinite-canvas/releases/tag/web-v2.0.0-beta.3)，仅支持Apple Silicon macOS，beta.3地址为`http://localhost:3100`。beta.4候选默认从3000启动，端口占用时顺延，以启动器显示的实际地址为准。旧Stable v1.2.8及3000/8888入口保持。预览版已在本机完成公开首装、跨版本升级和目标启动失败回退；另一台实体Mac尚未验收。

## 客户使用

1. 下载Release中的`Web-v2.0.0-beta.3-macos-arm64.zip`（展示标签为中文），解压后双击`安装工作台.command`。安装器联网取得本Release的签名清单，核验固定可信公钥、全部库存、Node和系统助手。Source code ZIP不是客户安装包。
2. 双击`启动工作台.command`，打开`http://localhost:3100`。包内带Node，无需安装npm。端口被占用时不接管或强杀未知进程；先正常关闭占用该端口的工作台。
3. 旧3000/8888用户先在旧版导出产品，再在新版点击“导入产品”新建独立画布；API凭据重新配置。当前不自动搬迁旧浏览器数据库、WebDAV或代理运行状态。
4. 后续在设置→软件更新检查、下载并暂存更新；确认画布已保存、任务已结束，再确认准备安装并关闭工作台页面。管理器重新验证包与身份、检查页面和持久任务、备份SQLite后切换。其他网站可继续使用。
5. “待核实”任务只有在渠道确认结束后，才能按实际结果处理；没有结果时使用“已结束且没有结果”核实入口，保留记录和审计，不能为升级删除任务或重新生成。

GitHub会净化中文资产名，远程固定为`Web.json`、`Web.sig`和`Web-v版本-macos-arm64.zip`；本地清单、ZIP及签名描述保留中文。安装器只接受固定仓库`web-v*`预发布的匹配签名资产。

安装目录：`~/Library/Application Support/AI-Workbench-Web安装`；个人数据：`~/Library/Application Support/AI-Workbench-重建版/工作区`。版本目录与SQLite、媒体、凭据分开。升级不清空数据；Origin/schema不匹配则拒绝就地升级。目标启动失败时保留或恢复旧版本。

若出现“保存尚未确认”，编辑仍保留在当前页，先使用“重试未确认保存”并等待“已保存”，不要刷新或关闭。beta.3本机首装验收曾出现一次新页保存未确认，原操作重试后恢复；后续冷启动与设置往返通过，但首次失败根因尚未确定。崩溃遗留安装锁也尚无自动恢复入口，不可直接删除锁强启。

## 开发、构建与签名

根`扩展功能/`是业务唯一来源，根`上游适配/`保存锁定作者提交的有序单功能补丁；`.运行/`是生成输入和私人证据，不提交。不要将运行副本变成第二业务来源。

在发布检出、macOS arm64及Node24环境执行：

```sh
npm run web:test-update
npm run stable:runtime -- arm64
npm run web:build -- output/stable-runtime/arm64
```

构建在`.运行/Web客户包/构建-*/`生成中文ZIP、逐文件库存及`构建结果.json`。前后端使用锁依赖，从作者固定Git SHA取源码；不复制工作簿、数据库或已安装助手。构建不打开工作台端口或Keychain。输入变化即失败；脏树候选`releaseReady:false`，不允许签名。

在干净固定提交上构建并按`开发文档/Web发布版本.json`建立匹配标签，所有者本机签名/发布命令：

```sh
node 开发工具/签名Web客户包.mjs /绝对路径/构建结果.json /既有加密签名备份目录 RELEASE-WEB-PREVIEW
node 开发工具/发布Web预览版.mjs /绝对路径/构建结果.json RELEASE-WEB-PREVIEW
```

入口限定GitHub所有者Champion-Guan（87700227）、干净提交和标签，复用原固定公钥及Keychain保护的原加密签名材料。不得换密钥、降低验签或将私钥放参数/聊天/环境。先上传Draft并下载复核，再公开预发布，不替换Stable。已发布beta.3标签及签名包固定；后续文档提交不覆盖它，代码修复另发新版本。

## 2026-10-23 保存与端口修复

beta.4候选修复受控会话续期成功但响应丢失后的重试不匹配：相同续期请求返回原续期结果，客户端仅对连接类续期失败自动重试一次，不重复签发、不延长页面授权。过期后新保存通过原页面会话重新连接。业务保存仍保留操作编号；未知保存回执和版本冲突不自动重放或覆盖。

开发入口和新客户管理器统一从3000尝试，EADDRINUSE时顺延到下一个端口，全程只绑定回环。页面授权、数据API、代理、生成和更新均使用实际地址。客户启动器读取与本次进程、工作区和已提交版本绑定的运行地址，不显示遗留地址。旧beta.3管理器在本次升级中暂时保持3100兼容；升级后正常冷启使用自动端口策略。签名库存的旧Origin字段仅保留协议身份兼容用途。

本次开发验证：旧3000 PID1055保留，新开发进程实际选择3001，原工作区UUID一致，原画布20节点恢复并显示已保存。设置修改及还原后落盘，SQLite五类分片图完整，原媒体、引用、任务和审计未变化。定向检查162项通过，完整TypeScript及源码装配引用检查通过。首次beta.3首装失败仍未捕获具体错误码，不能将本次确定的续期缺口认定为那次失败的已证实根因；本次增加分片/根提交/准备保存阶段和错误码诊断。

回退保留在开发目录既有`.运行/开发回退/`中，不用源码回退覆盖工作区数据。签名包及客户升级验收另行记录，未公开前本候选不替代beta.3。

# Web客户安装与升级

仓库固定为`Champion-Guan/infinite-canvas`。2026-11-10已发布beta.28客户预览版，增加一键超人、参数图片原图预览、待确认资料按卡片关联及共用变体提示词，并修复菜单定位、跨电脑画布导入与参考图检查等问题。构建、旧安装器兼容和匿名公开下载结果见[第二十八预览版发布验收](第二十八预览版发布验收20261110.md)。此前画布性能与交互改动及beta.26升级恢复修复继续保留。沿用原可信签名，仅支持Apple Silicon macOS；默认从3000端口启动，占用时顺延。下文的早期记录保留供追溯。

## 客户使用

1. 下载Release中的`Web-v2.0.0-beta.28-macos-arm64.zip`（展示标签为中文）。首次安装解压后双击`安装工作台.command`。安装器联网取得本Release的签名清单，核验固定可信公钥、全部库存、Node和系统助手。Source code ZIP不是客户安装包。已有beta.24且恢复失败时，保存并完全退出浏览器后，直接运行新包内“恢复卡住的升级.command”，不要先执行安装工作台。它可能先完成原暂存版本；恢复后再从设置升级beta.28。本机客户更新模块匿名发现、系统curl公开包下载及验签通过；客户网络和实机升级仍需确认。
2. 双击`启动工作台.command`，按输出的实际地址打开。包内带Node，无需安装npm。3000被占用时自动顺延，不接管或强杀占用进程。旧beta.3管理器主持的首次升级仍暂用3100；新版管理器下一次正常冷启动即使用自动端口策略。
3. 首次安装、启动和每次版本更新完成后都会检查`~/Desktop/生图工作台.app`。入口只在缺失或属于本工作台时创建，不覆盖桌面上其他同名应用；它读取当前安装指针，因此更新和旧版本清理不会使入口失效。点击入口时，服务未运行会先启动当前版本，确认本机工作台健康后再打开实际的`http://localhost:端口`地址。
4. 2026-10-27起已移除“旧版整批迁移”。已有迁入产品、工作簿、素材和配置继续保留；日常产品导入导出、配置导入导出沿用原入口。下方历史验收记录仅说明当时的迁移流程。
5. 后续在设置→软件更新检查、下载更新。智能升级改动接入后的版本中，点击一次“安装更新”即可等待任务结束、暂存复核并自动保存全部已打开画布；收到保存回执后，当前标签页进入安装进度，成功后自动返回工作台。启用“空闲时自动安装”后，所有工作台页面停止交互至少60秒且无编辑或生成任务时自动执行同一流程。按2026-11-08最新要求，该开关在首次读取、尚无保存偏好时默认开启，客户可随时关闭；已有保存为关闭的选择继续保留。源码开发模式也可保存选择，真正安装仍需客户安装管理器。未取得新安装包的旧版本仍沿用原流程。
6. “待核实”任务只有在渠道确认结束后，才能按实际结果处理；没有结果时使用“已结束且没有结果”核实入口，保留记录和审计，不能为升级删除任务或重新生成。

GitHub会净化中文资产名，远程固定为`Web.json`、`Web.sig`和`Web-v版本-macos-arm64.zip`；本地清单、ZIP及签名描述保留中文。安装器只接受固定仓库`web-v*`预发布的匹配签名资产。

安装目录：`~/Library/Application Support/AI-Workbench-Web安装`；个人数据：`~/Library/Application Support/AI-Workbench-重建版/工作区`。版本目录与SQLite、媒体、凭据分开。升级不清空数据；Origin/schema不匹配则拒绝就地升级。目标启动失败时保留或恢复旧版本。

若出现“保存尚未确认”，编辑仍保留在当前页，先使用“重试未确认保存”并等待“已保存”，不要刷新或关闭。beta.4修复了受控会话续期响应丢失后的恢复缺口，并增加保存阶段与错误码诊断；未知保存回执、版本冲突仍保留保护。beta.3本机首装首次失败的具体根因未捕获，不能认定与该续期缺口相同。崩溃遗留安装锁也尚无自动恢复入口，不可直接删除锁强启。

## 开发、构建与签名

根`扩展功能/`是业务唯一来源，根`上游适配/`保存锁定作者提交的有序单功能补丁；`.运行/`是生成输入和私人证据，不提交。不要将运行副本变成第二业务来源。

在发布检出、macOS arm64及Node24环境执行：

```sh
npm run web:test-update
npm run stable:runtime -- arm64
npm run web:build -- output/stable-runtime/arm64
```

构建在`.运行/Web客户包/构建-*/`生成中文ZIP、逐文件库存及`构建结果.json`。前后端使用锁依赖，从作者固定Git SHA取源码；不复制工作簿、数据库或已安装助手。构建不打开工作台端口或Keychain。输入变化即失败；脏树候选`releaseReady:false`，不允许签名。

在干净固定提交上构建并按`开发文档/Web发布版本.json`建立匹配标签，所有者本机签名/发布命令：

```sh
node 开发工具/发布Web预览版.mjs /绝对路径/构建结果.json RELEASE-WEB-PREVIEW
```

## 旧版本退出连接遗留恢复（beta.23）

旧版页面关闭请求断线时，后台可能仍保留已退出页面的授权，表现为长期停在“等待工作台页面关闭”。升级尚未完成时，新包中的前端修复还未生效。beta.23增加退出失败后的自动重试，并在安装包提供“恢复卡住的升级.command”。复现和验证边界见[升级等待页面卡住修复](升级等待页面卡住修复20261102.md)。

恢复入口不能在浏览器仍打开时继续，也不会强杀任务、删除锁或清空个人数据。没有暂存包、签名或工作区不匹配、旧服务拒绝停止时会明确报错并停止；它不处理未知崩溃锁。Mac B实机恢复仍需目标机器确认。

# 跨电脑画布 ZIP 保存修复

## 问题与原因

用户提供两份原始 ZIP：蜡烛共用尺寸画布（34 节点、33 连线、37 媒体），以及 Mac B 导出的未命名产品5（1 参数卡、2 主图）。文件均完整，但项目 JSON 分别包含 62 和 3 处来源浏览器临时 Blob 地址。

旧导入仅重映射部分 storageKey，遗漏 productMainImageStorageKey 和 JSON 字符串中的策划来源快照；旧临时地址仍进入接收端 SQLite 值编码。接收端无法读取来源浏览器的 Blob，保存失败，未确认画布刷新后消失。

## 修复范围

- 新建产品导入、当前画布追加及产品导出共用 `扩展功能/画布导入/便携媒体引用.ts`。
- ZIP 只保留稳定媒体键，接收端按本地键恢复显示地址；兼容已有 ZIP，不请求来源浏览器地址。
- 重映射主图单图别名、图片槽位、原图和交付图、聊天参考、回收站关联快照，以及策划来源指纹与参数快照。
- 只更换指纹中的媒体位置，不重新计算商品资料，保留原有提示词失效原因。
- 旧版失败追加后，单图别名仍指向来源键时，只凭同一主图地址与实际已打包主图的对应关系修复。
- 无法定位到打包文件的临时媒体在应用产品前拒绝；导出缺失原图时明确失败，不再静默输出不完整包。
- 图片原件按原字节保存；本次未改变数据库结构、保存恢复协议或任务执行方式。

## 验证

- 新增 8 项回归覆盖旧临时地址、主图别名、嵌套快照、当前画布追加、不完整包拒绝、便携导出、原有失效来源保护，以及空白接收端媒体和产品落盘后冷重开。
- 两个用户原始 ZIP 分别经过真实 SQLite 空白接收端导入、落盘确认、关闭、冷重开，再导出并重复导入、冷重开；节点、连线和媒体数量不变，每个媒体字节相等，读取来源 Blob 次数为 0。
- 蜡烛包内各提示词在导入前后的资料变更检查结果一致。
- 58 项导入、回收、主图、历史和产品切换回归通过，完整 TypeScript 检查通过。
- 当前开发服务自动构建成功，修复已进入本地静态产物。尚未发布新客户安装包。

## 当前浏览器现场

原页面停留在旧代码的一次失败追加：未命名产品7 内有两张参数卡，其中一张包含 Mac B 的两张主图。未直接丢弃该页，先通过原导出按钮保存到用户下载目录的 `未命名产品7-未确认导入恢复.zip`。

该恢复包已核对为 2 节点、2 媒体，并通过新代码的空白 SQLite 冷重开及重新导出往返验证。

重新加载页面时浏览器弹出未保存更改确认，本次取消了确认，原页仍保留内存内容。当前浏览器刷新后的实际恢复，以及 Mac B 安装版实机仍待验证；合成接收端验证不等同于这两项实页验收。

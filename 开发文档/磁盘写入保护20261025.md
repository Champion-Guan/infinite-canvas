# 磁盘写入保护

本轮沿用唯一根来源、小功能模块和现有开发工作区，不创建源码或数据备份。

| 写入入口 | 处理方式 |
| --- | --- |
| 自动备份及源码快照 | 启动、定时、维护和开发构建均不自动创建；用户明确手动备份时才执行 |
| 开发服务、客户服务及生命周期日志 | 单份最多2MiB、保留3份，持续轮换，正常日志不因容量上限停止；历史超大日志保留尾部归限；文件故障恢复后后续写入恢复 |
| 更新包下载 | 签名协议单包最多256MiB；只保留一个包及清单签名；同包重复点击或服务重启重新验签、核对摘要并复用；换包前清旧包，失败清半成品 |
| 开发版版本识别 | 更新检查使用本项目Web发布版本，避免上游基线0.20.0将已安装Web版误判为新版本而反复下载 |
| 安装完成 | 新版本健康检查及版本指针提交后清已安装下载包和待安装记录；下次启动补清中途退出遗留，不删正在下载的新版本 |
| 安装版本 | 保留当前、上一及事务仍引用的待安装版本；启动清中断解压，解压前检查2GiB预算（含512MiB解压预留）及1GiB磁盘余量 |
| 客户包构建 | 唯一构建锁；总目录预算4GiB，开始前计入本次1.5GiB余量并另保留3GiB磁盘；npm、类型检查、Vite、Swift和ZIP由独立守护持续监测容量、余量和超时，主构建退出则停止自己的命令进程组；npm缓存和Swift缓存归本次构建；finally清依赖、缓存或失败半成品；下次构建回收异常退出遗留；失败记录轮换保留2份、每份64KiB |
| 开发产物 | 512MiB预算、预留本次64MiB及1GiB磁盘余量；Vite纳入独立守护持续监测，静态包覆盖旧产物，Vite缓存finally清理 |
| SQLite | 256页自动checkpoint、16MiB日志回收阈值；长读事务阻止回收则暂停新增业务写入，读取释放后恢复；保留1GiB磁盘余量 |
| 媒体暂存及失败手动备份 | SQLite取得独占锁后清约定暂存名；写媒体失败清暂存及本次新建且未索引的文件，原有媒体保留；手动备份失败清本次半份目录 |
| 私人配置及安装状态 | 共用原子写保护：暂存最多16份/128MiB、单次32MiB、保留1GiB磁盘余量；安装状态另限16KiB；死亡PID的暂存下次写入回收，旧无PID格式超过24小时才回收，原配置及活跃暂存保留 |
| 代理缓存 | 活跃目录256MiB、父目录512MiB（启动预留256MiB），磁盘保留1GiB；容量监测超限停止自己的核心；目录所有者与守护PID均结束后回收中断目录，未知旧目录计入预算而不盲删 |

普通运行日志与SQLite事务日志用途不同。运行日志通过轮换继续保留新故障，SQLite事务日志涉及保存一致性，不能强删或在未回收时持续追加。产品、媒体、配置和幂等操作记录均不按缓存清理。用户主动新增的正常业务数据仍会占用存储空间。

构建及代理按周期采样，采样间隔中的瞬时写入可能暂时超过目录预算，不能称作文件系统硬配额。保留的磁盘余量用于吸收这些写入。容量异常会停止相应生成进程，不自动删除客户业务数据。历史分片仍用于恢复和内容复用，本轮没有未经会话协调的分片GC。

实现来源：`扩展功能/本机服务/有界运行日志.mjs`、`目录容量限制.mjs`，`扩展功能/本机存储/写入空间保护.mjs`，`扩展功能/软件更新/更新缓存限制.mjs`，`扩展功能/客户安装/安装版本清理.mjs`，`开发工具/Web构建占用保护.mjs`。接线与SHA登记于根`上游适配/开发源码映射.json`，运行副本由装配生成。

验收入口：`npm run test:disk-guards`，包含真实日志轮换、超限后新故障记录、文件故障恢复、容量和余量拒绝、单包下载及安装后清理、版本保留、构建互斥和失败回收、SQLite长读阻塞及释放恢复，以及已有签名升级、数据一致性和关闭自动备份测试。客户安装保护进入下一次重新构建并发布的包，旧已发布包不会被本机源码修改追溯更新。

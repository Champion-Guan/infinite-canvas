## 3. 主要发现

1. 原版的扩展协议是真实的**节点插件**机制，不是完整应用插件框架；参数卡可以迁为插件，产品胶囊/全局设置/跨产品结果等不能假装已有接口。
2. 旧版产品生命周期依赖 iframe 缓存和 DOM 重排。应迁业务身份与保存/任务规则，而不是迁整个旧工作台壳。
3. 原版画布仓库没有工作簿/产品归属，插件私有存储也不自动按画布隔离。需要稳定 ID 与明确存储责任，不能按标题或全局临时变量关联。
4. 旧版尺寸主题识别、用户编辑保护、原图/最终图已有可提取规则；不能只搬 UI 按钮而忽略生成/存储链路。
5. 原版资产文件 drop 不等于侧栏素材 draggable；侧栏资产拖入须单独实现/验收。
6. 原版回收墓碑不含完整快照；Guan 恢复功能要明确保存范围与媒体引用。
7. 当前原版浏览器保存密钥并直连 API，且存在 URL 导入渠道凭据。目录隔离不是密钥安全；网关接管必须覆盖所有启用入口。
8. 原版和旧版任意 JS 插件/脚本没有全面权限沙箱；第一轮客户产品只接入审查过的插件，不能声称所有旧脚本都安全兼容。
9. 旧测试含源码结构断言，能证明结构但不能证明弹窗可关闭、连线不跳或真实 FPS。后续需真实隔离浏览器流程与性能记录。
10. 不先叠加全局苹果动画。先保留作者 UI、验证稳定业务与热路径，再按组件生命周期接入，避免重现闪烁/遮罩卡死。

## 4. 已知原版类型错误：方案已核对，尚未修复

阶段 2 实测 `typecheck` 报 `web/src/components/layout/model-script-editor.tsx:58` 的 `styles.content` 不被接受。本阶段核对冻结安装的 Ant Design 6.6.5 `es/modal/interface.d.ts`：Modal styles 支持 `container`，不支持 `content`。源码使用 `.ant-modal-container` 也与此语义一致。

最小候选是将该处 `content` 改为 `container`，保持样式值不变。但此处阶段 3 没有改动；候选必须在阶段 4 给用户具体 diff，再仅作用运行副本。不得 `as any`、忽略报错或靠换依赖版本掩盖问题。阶段 4 的批准及实测结果见 [测试与性能基线](阶段4测试与性能基线.md)，不追改阶段 3 的历史测试结论。

上游当前没有新提交可直接修复。原版完整单测仍因本机缺 Bun 未执行；阶段 2 的 build 因 typecheck 失败未继续。本阶段只做静态复核，没有重跑业务 build/typecheck，也不将原版称为已可正式发布。

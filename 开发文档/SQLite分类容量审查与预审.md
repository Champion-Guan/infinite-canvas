## 展示与统计口径

保留原设置面板的分区、圆角、间距、刷新按钮及浅色/深色样式。新增分类进度条和三项总览：

- 当前业务内容：当前根、当前可达分片正文、普通业务文档与当前引用媒体的去重容量。
- 本机实际占用：SQLite、WAL、SHM与媒体目录普通文件的长度总和；属于采样值，不含备份、源码、运行日志。不是APFS实际分配空间，也不是剩余磁盘容量。
- 历史与保留内容：旧代/未发布分片正文及当前未引用的已索引媒体。这不是“可以安全删除”的容量。

分类包括图片、图片缩略图、视频、音频、通用媒体索引、提示词缓存、画布与应用配置、图片/视频生成记录、其他媒体、跨分类共享内容、其他扩展数据、历史分片及当前未引用媒体。

重要区别：

1. 业务记录数来自当前namespace的逻辑entries，不能将根/分片数当成卡片数量。画布与应用配置可能是一条含多个产品的状态记录。
2. 图片/视频/音频依据应用值的媒体描述MIME识别，不能仅看媒体表常见的`application/octet-stream`。
3. 文件数按`mime + size + parts`描述去重；容量按全局唯一媒体块去重。同一文件被多个记录引用不会重复加容量。
4. 跨类别共享的媒体块或当前分片正文放入“跨分类共享内容”，不同时叠加到两个分类。
5. 通用媒体索引保存逻辑记录；视频/音频分类展示相应文件容量，两者不会重复计算正文。
6. 分类总和等于文档正文与已索引媒体总和；不能再与数据库物理文件大小相加。
7. WAL内可能包含数据库页的历史版本；文件大小变化不代表业务内容同等增长。
8. 未索引/暂存媒体仅计入实际占用明细，不冒充已保存的业务内容；不自动整理或删除。

## 数据链路与安全边界

用户故事：打开存储页签或手动刷新，经既有授权客户端请求`GET /usage`，后端读取只读业务快照并采样文件长度，面板展示分类和错误状态。

| 边界 | 证据 |
| --- | --- |
| 自有React面板呈现 | 浅色、深色和390px窄屏截图；无横向溢出 |
| 面板到API | 既有自动握手与续期客户端；不手填授权码、不新增匿名生产接口 |
| API到SQLite | 内存候选真实HTTP测试，独立只读连接和事务；支持v1/v2及超过1000条历史分片 |
| 数据到响应 | 分类加总、全局去重、33MiB视频重复块、共享正文及并行写快照测试 |
| 响应到界面 | 新增第二条提示词后点击刷新显示2项；503时保留旧结果并说明不是当前容量，恢复后可重试 |

后端不读取媒体正文，不解密API Key，不返回正文、标题、秘密引用、数据根路径或SQL。媒体文件仅核验类型、权限、链接和长度；容量统计**不代替**媒体内容哈希校验，现有媒体读取/备份继续负责完整性验证。

Host、Origin、Bearer、会话有效期、CSRF、限流和写入协调保留。异步扫描结束后再次确认会话未过期或撤销；失效时不交付结果。

独立只读事务不占用原写连接。同工作区同时请求合并为一次在途扫描，完成后不缓存。每128次处理主动让出事件循环；没有新增周期扫描或画布逐帧订阅。

现有自动启动入口原本会调用一次`/usage`验证连接，因此接入本批后启动时也会进行分类读取。不是只在设置页读取。当前测试不构成百万记录容量或整项目性能优化承诺。单次安全上限为10万文档/10万媒体索引；分片图沿用既有32MiB/4096块等限制，超过时明确报错，不静默少算。

# 工作台交互排查清单

先走真实使用路径，再按证据逐个修。局部反馈和后台完成是两个时点：勾选、选中、输入、拖动应在下一帧就有可见变化；生成、导入等需要等待的命令先显示已接收，再确认成功或失败。只有存在数据丢失风险时才阻挡后续操作。

## 已定位

- 提示词变体勾选：之前受控复选框要等 50ms 合并才更新；「全选」对勾还有 160ms 动画延迟，单项勾选还会尝试横向居中。现在视觉状态仍由原生 input 当场切换，同时恢复约 120ms 的背景、边框和对勾过渡，动画零延迟启动；同卡片的单项和全选共用一次画布事务，按点击顺序提交，SQLite 保存不阻挡反馈。
- 侧栏页签：普通来源默认展开，但按可见区域读取；首屏只读取露出的来源，滚动后再读取其他来源，长列表也按滚动分批显示。搜索仍覆盖未滚到和折叠来源。Chrome「主图12」真实切换与滚动验收通过，未新增控制台错误。
- 节点拖动撤销：真实拖动确认节点落位立即反馈，但旧逻辑的撤销按钮会在历史合并延时后才启用。现在拖动释放作为离散编辑立即提交历史，文字编辑仍保留合并延时。
- 画布菜单：旧版从菜单项按 Escape 后焦点落到页面根节点；新版将焦点还给菜单按钮。鼠标点击菜单外的设置按钮或产品页签，原有操作仍会执行，菜单保留退场动效。
- 侧栏搜索：节点、资产、提示词库的输入框独立更新文字和光标，列表筛选走低优先级更新；组字事件结束后才提交查询。Chrome 实测节点搜索中文剪贴板粘贴和清空、资产回显、提示词库快速换词和折叠来源搜索通过。
- 输入验收：在 Chrome「主图12」的节点搜索里用 macOS 拼音输入 `tui`，组字期间列表保持原样，按空格提交「腿」后才筛选，按 Esc 取消则保留列表。提示词放大编辑器曾在同步浏览器生成的分行结构时丢换行；新版实测双 MIME 多行粘贴、移动光标继续输入、撤销及小框保留空行和末尾换行通过。原文已恢复，工作台显示已保存。
- 提示词弹窗：Chrome「主图12」的「反推提示词」浮层曾挡住放大编辑窗与提示词库，并仍可接收点击。新版两条路径均实测原浮层隐藏且不可操作、前台输入可聚焦、退场后浮层原位恢复且正文不变；大编辑窗用关闭按钮、提示词库用 Esc，焦点分别回到各自入口。未应用提示词或触发生成。

- 「主图12」226 节点画布：当前 Chrome 构建记录 121 次可信点击（71 次复选控件、50 次变体文字），包含单项连点和与全选交错。未新增 React 错误；所采样帧卡片与标题始终存在，可见全选、半选、未选三态，结束时界面勾选恢复到原值。多个输入可落在同一帧，未按逐点击延时验收。页面仍显示「保存失败」；未刷新覆盖未确认编辑，未验证落盘，也未触发生成。装配回归覆盖方框、标签和变体按钮不进入卡片选中，卡片空白和其他节点保持原逻辑。

## 上传与导入实测

- 本机 Chrome：顶栏导入、上传资产和当前画布导入共三个系统文件选择器均可取消。测试结束返回「主图12」，仍有 226 个节点，显示已保存。
- 顶栏导入：坏 ZIP 显示读取进度，随后转为「导入未完成」；合法 ZIP 新建独立验收画布，保留原产品并报告保存完成。读取期间原产品页签被禁用；错误详情直接显示 `invalid zip data`。
- 验收画布：坏 PNG 提示 1 个文件上传失败且不增加节点；有效 PNG 出现图片节点。坏 ZIP 无追加，合法 ZIP 只追加 1 个节点并显示已保存。当前画布坏 ZIP 的提示也直接包含英文解析错误。
- 小文件未观察到明确的上传中状态，不能据此判定大文件处理期间的首帧反馈及界面响应。未触发生成，独立验收画布保留以供复查。
- 侧栏「资产 → 添加」：本机 Chrome 选择两份各 24 MiB 的临时坏 PNG，观察到「正在添加资产… 1/2」；最终中文提示列出两份失败文件，未新增资产，「添加」按钮恢复可用。坏图后续传合法图片由定向测试覆盖，极慢上传期间的响应耗时尚未量化。
- 外部文件拖入画布：用户在 Chrome「保存恢复实页验收（合成）」以 `失败图片.png`（无效图片内容）+ `不支持.txt` 混合拖入，下一帧出现「1 个文件格式不支持，未添加：不支持.txt。画布支持拖入图片、视频和音频。」随后出现「有 1 个文件上传失败，请重试。」；画布元素数始终为 1，最终回到「已保存」。单个 `.txt` 拖入也已通过实页验收。

## 生成状态实测

- 在现有 Chrome 工作台的「生成状态验收（本地模拟）」画布选择专用模型，使用合成提示词；匹配模拟地址的响应在本机生成，不请求真实渠道。
- 点击后首个页面采样显示「生成中」和「停止」。18 秒模拟等待内执行了空白处拖动，并确认缩放从 100% 到 99%。未采样首帧耗时，也未单独量化平移距离。
- 模拟 HTTP 400 后卡片显示中文失败原因和「重试」；到「已保存」后刷新，原失败原因仍在。未执行手动重试。
- 模拟提交回执丢失并延迟首次查询时，卡片仍只显示「生成中」，没有区分与渠道等待的状态；最终显示原任务的明确拒绝。实页未独立核对提交计数，不重复提交由 HTTP 闭环回归覆盖。本轮未实测成功出图。

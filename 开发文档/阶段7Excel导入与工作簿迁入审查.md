## 三、本批候选行为

### 导入与解析

- 顶栏“当前工作表”下拉可以上传 `.xlsx`、`.xls`、UTF-8 `.csv`。
- 沿用旧提示词矩阵规则，识别 Main Prompt、Detail Prompt、Rich Prompt 等列；Data 和前面的竞品分析工作表不误建为待生成产品。
- 保留旧产品预览、默认全选、逐项勾选、数量和错误文案；文件名、产品路线和提示词保持转义，不能作为 HTML 执行。
- 保留 100 MB 文件、10,000 数据行、200 列限制；读取、解析、结构检查、识别、文件指纹与保存使用明确阶段提示，不冒充连续字节进度。
- 取消读取后不接纳晚到结果；保存已经开始时不允许取消后冒充没有导入。弹窗有 Escape、Tab 焦点约束和关闭后焦点恢复。

### 工作簿与产品对应

- 同一个 SQLite `canvas_store` 根保存工作簿合同、产品和归属；不建立第二套画布库、不使用 localStorage/IndexedDB 回退。
- 一条勾选的提示词产品行对应一个稳定产品 ID 和独立画布；完整路线不同，即便显示名相同也不合并。
- 顶部胶囊只列出当前工作簿产品，导入顺序沿用 Excel；每个工作簿分别记住当前产品，空工作簿不跳到其他工作簿。
- 重传同名文件和同一工作表时，优先当前已有版本；按完整路线优先、旧模板 ID 次之匹配。更新来源及模板，保留产品 ID、节点、连线、生成结果、任务及人工改名。
- Excel 删除行不会自动删除已有产品；回收产品不会被重传悄悄复活。
- 无归属字段的历史产品只在首次导入时归入当前工作簿，ID 不变；明确 `productSetId: null` 的产品保持未关联，并有可访问的下拉分组。
- 新建/普通画布导入归属当前工作簿；保存失败后归属仍以实际打开的产品为准，不被尚未确认的目的工作簿抢走。
- 删除最后一个产品只回当前工作簿首页，不串到其他工作簿；恢复产品允许切回其原归属。

### 保存与失败处理

顺序为：当前画布真实 React 检查点 → SQLite 确认 → 读取最新根并规划 → 一次发布整份工作簿和产品关系 → SQLite 确认 → 保存选择偏好 → 导航。

复用现有产品操作锁、保存检查点和恢复挂载门禁。新产品发布前先阻止挂载，业务根与导航偏好确认后才释放目标产品。失败保留完整内存数据、原画布和既有待确认队列，不删新产品、不自动刷新、不跳页冒充成功。用户先通过现有保存状态栏重试，再显式选择工作簿继续；不要重复上传制造第二份操作。

页内待确认队列不是断电/刷新恢复保证。文件原始二进制不会自动归档，保存的是文件指纹、解析模板和来源信息，不能宣称可原样导出原 Excel。

# 受管理 Chrome 扩展

## 用途

`browser/managed-workbench` 是可选的本机维护扩展，不是工作台运行、生图、Agent 或普通更新检查的依赖。它主要用于：

- 观察当前 Chrome 配置中指定本机工作台 Origin 的标签页和 frame，并把有限的匿名化状态交给本机只读桥接。
- 在工作台页面配合维护协议报告应用版本、活动计数和保存状态；生产桥接当前只观察/探测，不发送暂停、恢复或安装命令，也不授予安装许可。
- 仅在本机已经启动明确的数据迁移会话时，配合 5174→8888 或 8888→3000 的浏览器存储迁移；它只创建、关闭自己创建并验证过的临时标签页，不会在日常浏览时复制数据。

没有该扩展仍可直接访问工作台并使用普通功能。移除扩展不会删除画布、设置、图片或浏览器数据；迁移进行中除外，应先结束迁移。

## 权限与数据边界

- 当前扩展版本：`1.0.4`。清单权限为 `nativeMessaging`、`webNavigation`、`storage`；没有 `debugger`、Cookies、浏览器历史或任意网址权限，也没有单独申请 `tabs` 权限。
- Host 权限仅匹配本机 `localhost/127.0.0.1` 的 3000、8888 和旧 `127.0.0.1:5174`；内容脚本运行在隔离世界。无其它网站页面内容读取能力。
- `storage.local` 只保存随机生成的 profile 会话标识。普通观察会传给本机桥接有限的 tab/window/frame/document 标识、生命周期和版本/活动状态；不会传页面路径、标题、查询参数、DOM 内容、提示词、API Key、图片或画布内容。
- 普通观察不会读取 `localStorage`、IndexedDB 或业务文件。只有显式发起 Origin 迁移时，迁移 relay 才按迁移协议读取并复制浏览器业务存储；数据仍在本机两个 Origin 之间处理，不通过扩展上传到外网。
- 只读桥接仅接受受限的 inventory/unknown 报告。它明确标记 `profileOnly=true`、`inventoryVerified=false`、`installAllowed=false`：只能说明当前配置的观察结果，不能证明其他 Chrome 配置、浏览器或任务均已空闲，也不能单独允许安装。

## 当前限制

- 点击扩展图标会连接观察桥接并打开 `http://localhost:8888`。这仍是兼容旧 Stable 地址的固定入口；Mac A 源码工作台当前运行在 `http://localhost:3000`，所以在 Mac A 点击扩展图标不会打开当前源码服务。日常请用桌面 AI-Workbench 快捷方式或直接打开 `http://localhost:3000`。
- 如果未安装本机只读桥接，扩展可能显示 `!`；这不影响工作台本身。蓝色数字只代表扩展观测到的当前 Chrome 配置中的工作台标签数，不代表任务安全、全局空闲或允许自动安装。
- 扩展依赖用户把解压目录加载到实际使用的 Chrome 配置。它不会更换 Chrome profile；更换 profile 后也不会自动看到另一个 profile 的数据。

## 桌面入口与在线更新

桌面 `AI-Workbench.app` 是本机启动器，不是扩展。启动器会先请求本机健康检查；服务已运行时直接打开 `localhost` 工作台，服务未运行时尝试启动对应的用户态服务。稳定版更新成功后，更新管理器会用新安装路径刷新这个项目自有的桌面入口，并打开工作台页面；来源模式重启也会刷新入口。若桌面已有同名但非本项目的文件，程序不会覆盖它。

## 人工安装与移除

把项目中的 `browser/managed-workbench` 目录加载到正在使用工作台的 Chrome 配置即可。早期维护验收还要求在本机单独安装只读 Native Messaging 桥接；不要把扩展 ID 或浏览器 profile 当作 API 凭据。

在 `chrome://extensions` 停用或移除扩展即可停止其观察与页面 relay。该操作不会清理 Chrome 的工作台存储、项目数据目录或桥接目录；如需清理桥接，应只按对应的本机卸载流程逐项核对，不能删除整个 Chrome 配置或 `Application Support` 目录。

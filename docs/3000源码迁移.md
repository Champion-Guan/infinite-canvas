# 源码工作台迁移到 localhost:3000

本次把新启动的 Web 服务默认端口改为 3000，并给 Mac A 的现有源码模式提供安全迁移。现有 Stable supervisor 和旧 5174→8888 工具仍按已安装的 8888 服务身份运行，不在本次源码切换中改写其安装指针。

## 操作与保护

先保存画布、结束生成并关闭 8888 和 3000 工作台页面，其他网站和应用不用关闭。操作者执行 `node scripts/start-source-workbench.mjs --migrate-port`。

脚本核验现有源码 launchd 描述、端口归属和页面关闭情况，在私人备份目录保存运行数据、原 launchd 文件和源码模式记录，再停止确切归属的旧工作台服务，启动 3000。启动失败恢复旧 launchd 服务；不强杀其他端口，不清空浏览器存储。

浏览器自动打开 localhost:3000 的迁移入口。点击保存关闭确认后，同一 Chrome 配置的顶层旧地址窗口导出完整 localStorage、sessionStorage 和 IndexedDB（含二进制记录），本机先写入并校验源和目标的完整备份，再复制到目标并逐项验证。

所有者已批准目标存在旧项目时定向合并：其他项目的配置和数据库保留；画布、资产按标识合并，不改标识；同名工作台配置采用 8888 的值，3000 旧值保存在 `browser-localhost-before.json`；同名提示词缓存保留目标值。相同标识但内容不同的画布、资产、图片和业务记录、未知源数据库、不兼容结构或备份后变化，均停止，不猜测覆盖。没有清空、删除数据库或删除记录的步骤。

完整规划与媒体解码在首个写入前完成。每个数据库使用事务写入变更，完成后重新导出全部数据逐项比对；服务端也从两份原始备份独立重建预期结果，核验后保存 `browser-localhost-merged.json` 及摘要回执才允许进入工作台。跨数据库事务不能整体回滚，失败时保留部分副本、禁止进入，不自动重复覆盖；此时原 8888 数据及两份完整备份用于恢复。

8888 只提供受限读取桥：会话绑定的导出页面及三个迁移/编码模块；不再运行旧画布或任何生成、凭据、代理 API。localhost:3000 页面在私人迁移回执和浏览器标记通过前不会启动工作台，避免初始化默认数据污染目标。旧 8888 浏览器数据永久保留，备份目录名为 `pre-port3000-*` 和 `localhost-*`，包含敏感信息，不得上传。

## 范围与待验收

这是源码模式迁移，不等于客户 Stable 更新器完成端口事务迁移。现有客户的 8888 Stable 安装继续可用；后续发布必须另行验证 Stable 安装指针、监督器、更新完成后的入口和旧客户端迁移兼容，不能仅更改端口常量就自动切换客户服务。

本机实际切换需要当轮保存关闭确认。隔离测试不代表本机真实浏览器数据已迁移，也不代表 Mac B 已验收。

# 独立更新进度窗口

适用于接入独立更新器的 Stable 工作台。Mac A 的源码开发模式只刷新前端，不安装 Stable。

## 客户操作

1. 下载进度仍在版本弹窗和软件更新设置中显示真实百分比，下载完成且验签通过后才能安装。
2. 保存画布和正在编辑的信息，结束生成任务，点击“已保存，关闭页面后安装”。
3. 浏览器会打开独立进度窗口。关闭所有 8888 工作台页面，保留进度窗口；其他网站和应用不受影响。
4. 窗口显示准备、停止旧服务、切换版本、启动与健康检查。安装步骤不显示猜测的百分比。
5. 成功后自动打开工作台。若未自动打开，可点击进度窗口的“打开工作台”。恢复旧版或安装受阻时，回到工作台查看原因并重新确认。

弹窗被拦截、进度服务无法启动或窗口在准备期间被关闭时，不发送安装确认。确认后的进度窗口只用于观察；关闭它不会取消已经确认的安装。需要取消时，在工作台选择“稍后安装”。

## 实现边界

- `src/server/update-progress.mjs`：后端启动固定脚本，握手取得随机本机端口和随机路径；只读 HTTP 页面、样式、脚本和状态。每个后端最多一个监控子进程，重复请求复用，最长运行一小时。
- `scripts/run-update-progress.mjs`：独立于工作台后端运行。后端退出或 IPC 断开不会终止窗口，定时读取既有独立更新器的用户私有 Unix socket。
- `src/server/software-updates.mjs` 与 `update-http.mjs`：只接受空的进度窗口请求，目标版本来自已验证的下载记录，浏览器不能指定程序、命令、路径、端口或仓库。
- `src/canvas/hooks/use-software-update-actions.ts`：设置页和版本弹窗共用确认流程，在用户点击事件中同步打开窗口，避免异步准备之后被浏览器拦截。
- 进度服务绑定 127.0.0.1 的独立随机端口，严格检查 Host、Origin、GET 和随机路径，不允许跨域、嵌入页面或执行安装命令，不暴露私有路径、凭据和用户内容。
- 8888 页面检查不统计该窗口。未知页面库存仍阻止安装，进度窗口不能绕过保存关闭要求、签名验证、确切进程归属或安全回滚。
- 只有本次目标版本的 committed 状态及 `service-ready` 归属/健康确认同时通过，才显示成功；恢复旧版也需要服务确认。连接中断显示重试，不推断成功。
- 准备请求最长等待 130 秒，与更新器 120 秒的内部准备上限对齐。网络断开后的结果仍须从独立窗口或工作台状态确认，不能根据 HTTP 超时判断安装结果。

## 验证

专项命令：`node --test tests/update-progress.test.mjs tests/version-update-entry.test.mjs tests/software-updates.test.mjs`。

覆盖只读访问、错误 Host/Origin、非法操作、真实服务确认、错误目标版本、全局安全阻断、并发窗口复用、父 IPC 断开、弹窗被拦截及进度服务故障不确认安装。另使用隔离浏览器验证等待、启动、成功、恢复旧版和深色主题的展示。演示状态不是 Mac B 实机安装证据。

2026-10-13 本轮完整回归 613/613 通过；后续窗口提示、源码模式禁用安装及冷启动阻断展示调整的专项复测通过。类型检查和构建通过，Lint 无错误、4 条既有警告。初次专项中的错误 Host 测试发现 Node fetch 忽略手动 Host，改用实际 HTTP request 后访问约束通过；不是放宽服务检查。源码及 Git 历史敏感扫描通过。

独立窗口的状态每两秒刷新，显示窗口总等待与当前步骤时间；超过一小时或服务断开时明确显示连接中断。返回工作台会重新计入页面库存，因此在安装过程中不要为了查看进度重新打开工作台。
